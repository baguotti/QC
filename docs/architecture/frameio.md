# Frame.io: upload, download, browser, comments

The Upload tab and everything that talks to Frame.io.

Section numbers match the old single AGENTS.md, so older commit messages and notes still point to the right place.

## 8i. Upload Tab → Frame.io (`FrameIO.swift`, `FrameIOUpload.swift`, `UploadTabView.swift`)

- **Auth**: Adobe IMS Native App credential (PKCE, no secret, redirect `adobe+…://adobeid/<client id>`) via `ASWebAuthenticationSession`; scopes `openid email profile offline_access additional_info.roles`. Tokens live in `Application Support/QCpie/FrameIO/tokens.json` (0600), not the Keychain: the app is ad-hoc signed, so the Keychain would prompt after every update. All network/token work runs on the `FrameIO` actor.
- **Queue**: the tab shows the app's queue (`playerTreeNodes`, shared with Play/Inspect/Scan); `UploadQueue.sync` mirrors it only while the tab is open (`.task(id: queueVersion)`), sizes read off the main thread. Image sequences read as one clip upload every frame. Selection is Finder-like (click, ⌘, ⇧, folder = its contents, ⌘A, Esc); empty selection uploads everything. Queue rows drag (the whole selection when the row is in it) as `UploadQueue.dragPrefix` text onto a Frame.io folder/project row or the open folder, which starts an upload of just those files there; only valid targets get a drop handler (`dropIf`). **Finder files and folders** dropped on the same targets (checked first: Finder also offers text) join the app's queue (`UploadQueue.addFromFinder` → `ContentView.loadAssets(_:append:onLoaded:)`, so sequences, subfolders and media filtering are the queue's own) and then upload just them there: `finderFilesQueued(version:changed:)` arms the drop with the queue version that holds them, and the first `sync(with:version:)` at or after it starts the upload (files already queued start at once). Non-media files are refused with a toast, since the queue doesn't take them.
- **Upload** (`UploadEngine.swift`, `UploadResumeStore.swift`; `UploadQueue` in `FrameIOUpload.swift` is only the UI state): `POST …/folders/{id}/files/local_upload` → PUT each pre-signed part (`x-amz-acl: private`, `Content-Type` = the upload's `media_type`), parts map to the file in array order; there is no completion call, `GET …/files/{id}/status` confirms (only `upload_failed` fails a file). Parts from up to 6 files share one pool of streams (`TransferGate`): starts at 6, +2 every 5 s while all streams are busy and speed still grows (≤ 16), −2 after network errors. Part bodies are **streamed from disk** (`PartBodyStream`: a pump on its own concurrent queue reads 1 MB at a time into a 4 MB bound stream pair whose input end is the request body, with an explicit `Content-Length`; S3 pre-signed PUTs reject chunked bodies). Parts grow with the file (86 MB at 3 GB, ~370 MB at 13 GB); reading them whole under the old 512 MB memory budget left one part in flight for big files, alternating read and send (bursts to 128 MB/s, then ~0). Memory is now ~4 MB per stream. While the stream buffer is full the pump backs off from 0.2 to 5 ms (polling every 0.3 ms meant ~50,000 wake-ups a second across 16 streams on a slow line). The pump reopens the file on every attempt, and blocking reads from a slow network drive never hold the shared task threads. The upload `URLSession` allows 32 connections per host (the default 6 capped everything), waits for connectivity and has no cache. **Never memory-map source files**: a mapped file on a network volume that disconnects crashes the app (SIGBUS). Files with the same name and size already in the target folder are skipped, unless they are unfinished placeholders (`status: created`). The **Keep subfolders** switch in the "Upload to" card: off (default) puts every file in the chosen folder; on recreates the queue's subfolders under it (`FolderResolver`, deduped, failures not cached). The skip check also matches a version stack's current version (`head_version`).
- **Retries**: network errors (`URLError` connection lost / offline / timeouts …), 408, 429 (Retry-After), 5xx and S3 `RequestTimeout` retry with backoff 1–30 s ± 25 %, after `NetworkMonitor` (NWPathMonitor) reports the Mac online (`withRetries`); a part or call gives up after 15 min of failing while online (`giveUpAfter`; offline time doesn't count). Frame.io API calls (create upload, list / create folders, delete) retry the same way plus 408 / 429 / 5xx (`classifyAPI`, `RetryingAPI`); a create that needed a retry may have reached Frame.io the first time, so same-named empty placeholders (`status: created`, < 15 min old) are deleted. Errors shown in rows and the log come from `UploadEngine.describe` (URL errors otherwise read "NSURLErrorDomain error -1005"). 403/404 on a part = the links expired or the upload was dropped: the file starts over with a new upload once (Frame.io can't refresh links) and the old placeholder is deleted. A file whose size or modification date changes mid-upload fails and its placeholder is deleted (read with `FileManager.attributesOfItem`: `URL.resourceValues` caches per URL and hid changes). A failed read or a source drive gone for a moment (`UploadError.unreadable` / `.missing`) is retried like a network error, each attempt first checking the file is unchanged; it never deletes the placeholder (a server drive reconnecting used to throw away a 90 %-done upload). Parts may take longer than an hour on big files: the session's resource timeout is 24 h (an hour's cap resent such parts from zero forever). "Create upload" calls are paced at 5/s (`CallPacer`, Frame.io's limit).
- **Pause / resume**: every finished part is recorded in `upload-resume.json` and the run in `upload-run.json` (separate so a 10,000-frame sequence's row list isn't rewritten per part; 1 s after a change, and on pause / finish) with each file's placeholder, part links, sent parts and link expiry (`X-Amz-Date` + `X-Amz-Expires`), plus the run (destination, keep-subfolders, rows left). Pause cancels in-flight parts (they're resent) and deletes nothing; Resume — also after quitting, a crash or failed files (`UploadQueue.resumable`, the resume card) — continues each file from its next unsent part; files whose links expire within 10 min start over. Cancel (and Discard) delete the unfinished placeholders on Frame.io. Deletes are queued in the saved state (`PendingDelete`) until Frame.io confirms, and retried at the next upload and launch (`drainDeletes`). Quitting while uploading asks, then pauses, saves and quits (`pauseForQuit`, `.terminateLater`). Starting a new upload over a resumable one discards it but keeps placeholders of files it uploads again. The Mac is kept awake (`beginActivity`, idle system sleep disabled) while uploading.
- **Tests**: `Tests/UploadEngineTests.swift` runs the engine against `StubStorage` (URLProtocol) and `FakeFrameIO`: multi-part assembly, dropped connections / 503 / RequestTimeout retries, pause → quit → resume from disk (only unsent parts are sent, same upload), expired and near-expiry links, a file changed mid-upload, skipping finished vs unfinished files, a lost create reply (retried, twin deleted), a dropped folder lookup, pending deletes surviving a relaunch, giving up after the online time limit, the store round trip (parts don't rewrite the run file), error classes and the gate.
- **Performance**: `UploadQueue` and `FrameIOBrowser` are observed only by Upload-tab views, never by `ContentView`. The queue list (`UploadQueuePanel`) doesn't observe the browser; only `UploadControls` does. Row hover lives in each row (`HoverBackground`), never in list-level state (that redrew the whole list per mouse move). **Resizing** (measured with `ResizeBench`, 1900×1200 window, a Frame.io folder and a queue loaded: window resize 81 → 9 ms a frame, divider drag ~90 ms stalls → 13 ms): the tab's columns are a `Layout` (`UploadColumns`, clamps widths while placing), not a `GeometryReader` (that re-ran the tab and rebuilt the browser every frame); the queue panel sits in an `EquatableRow` keyed by `QueuePanelKey`; the breadcrumbs fit by measured text widths (`CrumbFitter`, cached, rebuilds only when the number that fits changes), never `ViewThatFits` (six variants with drop targets, hover and tooltips re-laid out per frame cost ~75 ms). Cost grows with window size: benchmark large. **`ResizeBench`** (debug only): `QCPIE_RESIZE_BENCH=<out file>` plus optional `QCPIE_BENCH_FAV=<favourite index>`, `QCPIE_BENCH_FOLDER=<queue folder>`, `QCPIE_BENCH_SIZE=WxH`, `QCPIE_BENCH_TAB`, `QCPIE_BENCH_HIDE=browser,drawer,queue,assets,header,crumbs,badge,account,drawertabs,favbar,toolbar,list` (`benchHides`); run `build/QCpie.app/Contents/MacOS/QCpie` with them. Uploads read the source drive at network speed: playing heavy media from the same drive during an upload can stutter.
- **Browser** (`FrameIOBrowserView.swift`): inside a project, rows select Finder-style (double-click or chevron opens a folder), the right-click menu uses **Frame.io's exact names, order and groups** (Create Share Link, Add to Share Links ▸ | Open in Frame.io | Copy Folder URL / Copy Asset URL, Copy to, Move to ▸, Duplicate, Rename; stacks add Version History), with renaming a stack renaming its current version, with QCpie extras (stack, favourites) after; keep new items consistent with the Frame.io web app; New Folder creates "untitled folder" and starts an inline rename. Rename and move update the list optimistically and show a toast with **Undo** (move back to the previous parent, rename back); the last change stays undoable (`lastUndo`) from the toolbar, the top of every right-click menu and ⌘Z (Upload tab only) until the next change; failures restore and show the error. Moves use the bulk endpoints (folders 10 calls/min, files 60/min, ≤100 ids per call), version stacks one by one; Frame.io items drag as `FrameIOBrowser.dragPrefix` text onto folder rows or parent breadcrumbs. **Delete** (`FrameIODelete.swift`, last in the menu as in Frame.io, or ⌘⌫ on the selection, rule `frameioDelete`): files, folders (with their contents) and stacks in a folder, versions in an open stack; never projects/workspaces/accounts. Always asks first (`NSAlert` sheet, Return = Cancel); no Undo (the API has no restore: the alert points to Frame.io's Recently Deleted). `DELETE …/files/{id}` (100/min) and `…/folders/{id}` (60/min); the V4 API has no stack delete, so a stack's versions are deleted one by one. Goes on past a failed item and reports it, stops when signed out; folders can't be deleted while an upload runs (one may be its destination). Deleted rows go at once and stay out of listings for 30 s (`recentlyDeleted`); favourites inside deleted places are removed. Tests: `Tests/FrameIODeleteTests.swift` (stub API: nothing reaches Frame.io).
- **Version stacks**: folder listings carry each stack's `head_version`; a stack's children come newest (current) first, so V*n* = count − index. Stack badges come from one children call per stack (first 25, cached in `versionCounts`, cleared after our own stack changes). Stack 2–10 files (`FrameIOStackSheet` orders them; last = current), Unstack (moves every version back to the folder), Remove from Stack (inside a stack), and dropping Frame.io files on a stack adds them as the newest version (file move with `parent_id` = stack). The API can't reorder versions or set the current one.
- **Create Share Link…** (right-click files/folders/stacks/versions, empty space, a project in the list, or toolbar Share): mirrors Frame.io's dialog. The share is created immediately with Frame.io's defaults (`access: public`, view/comment/download) and the link copied; then name, access (public / secure = invited only), email invites (`…/shares/{id}/reviewers`, message, notify toggle) and settings (link active, comments, downloads, all versions, passphrase, expiry) are edited in place. Updates are batched into one `PATCH …/shares/{id}` 0.8 s after the last change (10 calls/min); bodies are encoded on the main actor (`FrameIO.shareUpdate`) because `[String: Any]` isn't Sendable. The sheet has a fixed size (macOS sheets don't resize with content), so Settings is a second page. Plan-gated settings (e.g. `secure_sharing`) come back as 422 "not included in plan" and are explained, not shown raw. **Add to Share Link ▸** lists the project's shares (newest first, loaded on entering a project and after creating one) and adds assets one call each (`POST …/shares/{id}/assets`, 10/min).
- **Thumbnails** (toolbar toggle + size, `frameioThumbnails`): listings request `include=media_links.thumbnail,media_links.thumbnail_high_quality` (re-added on every page: `links.next` drops it); `FrameIOThumbnail` loads only for rows on screen, decodes off the main thread at ≤320 px (≤640 px from the high-quality link above 128 pt; slider 48–256 pt), cached by item / stack head (`FrameIOThumbnailCache`, capped at 64 MB of decoded pixels). Image server only, no rate-limited API calls.
- **Filter & Favourites**: the toolbar filters the open listing by name, locally (no API call; cleared on navigation; ⇧-click ranges follow the filtered order). Favourites are full crumb paths (`FrameIOBrowser.Favourite`) in UserDefaults `frameioFavourites`: star the open project/folder/stack, the star on a project row, or right-click → Add to Favourites; opening one restores the path and lists it by id. The project list has a **Favourites / All Projects** switch (`favouriteProjectsOnly`, UserDefaults `frameioFavouriteProjectsOnly`, default Favourites) that lists favourite projects only; folder/stack favourites, like projects, show as `FavouriteChip`s (icon, name, location; click opens, the current place is highlighted, × on hover or right-click removes; drag to reorder, `moveFavourite` + `FavouriteDropDelegate`, saved order). Layouts (`frameioFavouritesLayout`): **Bar** under the breadcrumbs (scrolls sideways) or **List** (a vertical popover from the toolbar's Favourites button); clicking Favourites switches Bar → List (opens it), in List a click while closed opens it and while open goes back to Bar; right-click picks one. (A Hidden layout was removed; an old "hidden" value reads as Bar.) **Pages**: up to 5 named tabs (`favouritePages`, UserDefaults `frameioFavouritePages`; shown page `frameioFavouritePage`), in the Bar and the List; each favourite is on one page (`Favourite.page`, older ones on the first), stars go to the page shown, right-click a chip → Move to Page or drop it on a tab; double-click a tab to rename, right-click to delete (its favourites move to the page before), + adds one. The project list's Favourites view and project stars count favourites on every page. The project list also has a **status filter** (Active default / Inactive / All Statuses, `projectStatus`, UserDefaults `frameioProjectStatus`) and Frame.io-style columns from the project fields (`updated_at` relative, `storage`, `created_at`, `status`; `ProjectColumn`, fixed widths scaled with Button Size; Workspace is omitted, it's in the breadcrumbs; the API has no item count) with the project icon from `image`. Folder and stack listings get the same treatment (`ContentColumn`: Last Updated, Size, Creation Date, Type from the file extension; pinned header). Stars use the accent colour, never yellow. Header/toolbar controls share `toolButton`/`toolLabel` with `ToolHover` (rounded hover background, filled while on); context-only controls appear only where they apply (New Folder in folders, New Project in a workspace's project list, view toggle in folders/stacks, Share where a share can be made). **New Project** (header button or right-click on the list) asks for a name (`FrameIONewProjectSheet`), `POST …/workspaces/{id}/projects`, then opens it; in the Favourites view it's starred so it shows there.
- **Breadcrumbs**: whole names (`fixedSize`), Finder-style: `CrumbFitter` measures the titles (cached widths) and shows the full path, else the last crumbs that fit with the rest folded into a "…" menu (click any to go there), and only the last crumb alone is shortened. The account is skipped when the workspace has the same name. Hover shows the full path.
- **Pasted links** (`FrameIOLink.swift`): ⌘V in the Upload tab (router rule `frameioPasteLink`, consumed only when the clipboard holds a Frame.io link) or pasting into the filter field go to the link's place (no button: ⌘V is enough). Shapes (from the API's `view_url`): `next.frame.io/project/{p}`, `…/project/{p}/{folder}`, `…/project/{p}/view/{file or stack}`; `f.io` short links are followed first. `resolve` finds the account that has the project (open one first), takes the workspace from the project, walks folder `parent_id`s up to the root (`FrameIO.item(account:kind:id:)`), and a file inside a stack selects the stack in its folder. The file/stack is selected and scrolled to once the folder loads (`pendingSelection`, `revealID`). Share/review links and old `app.frame.io` links are refused with a reason. Measured: 0.5–1.3 s per link.
- Queue rows: right-click → Play (switches to the Play tab), Reveal in Finder, Copy Path; folder rows → Reveal in Finder.
- **Upload & Share** (`UploadQueue.start(…, share: true)`, `shareRun`): after a run that wasn't paused or cancelled, lists the destination, matches the run's top-level names (files, or first subfolders with Keep subfolders), creates a public share (`createShare`) of those items — the folder itself only when it holds nothing else — copies the link and shows a toast. Resumed runs don't share. The transfer progress card (`TransferProgressCard`, uploads and downloads) is compact by default; a click shows the full card (`transferCardExpanded`).
- **Inline text fields**: `KeyboardShortcutRouter` unfocuses a text field on both Return and Esc and swallows the key, so `onSubmit` never fires there. Commit on focus loss and treat `NSApp.currentEvent` keyCode 53 as cancel (see `finishRename`). Sheets are the exception: the router returns every key untouched while the key window is a sheet (`sheetParent != nil`), so a sheet's Return/Esc reach its `.defaultAction` / `.cancelAction` buttons (give each sheet both) and ⌘Z/⌘A/⌘V never act on the window behind it. Don't add focus-loss commit handlers to sheet fields: with Return reaching the button, they'd run the action twice.
- **Status badge** (`FrameIOStatusBadge.swift`, Frame.io header): Frame.io's public status page (`status.frame.io/api/v2/status.json`, Atlassian Statuspage `indicator`: none / minor / major / critical / maintenance) as a dot and a word; hover shows Statuspage's description and when it was checked, click opens status.frame.io. Checked only while the badge is on screen, every 5 min (30 s after a failed check), off the main thread, on its own ephemeral session: each round asks `status.frame.io` and the same page on `fd8yftg0289n.statuspage.io` at once and takes the first answer (3 rounds, 5 s timeout). **Never set an `Accept` header** on these requests: the page is cached per `Accept` (`vary: Accept`), and the `application/json` copy, which almost nobody else requests, is nearly always expired and its refill hangs (measured: curl hung 6 s with it and answered in 20 ms without; URLSession with it timed out 3 of 4, the default `*/*` answered 16 of 16). That header was why the badge stayed grey. A failed check keeps the last answer until it's 15 min old; `FrameIOServiceStatus` is observed only by the badge. (`incidents/unresolved.json` hung for 20 s when tried, so incident names aren't shown.)
- **Downloads** (`DownloadEngine.swift`: `DownloadEngine` + `DownloadQueue`): right-click files, folders (their contents, structure kept), stacks (current version) or versions → **Download…**, or drag rows onto the Downloads drawer or its header tab (`DownloadQueue.acceptDrop`, the same flow), (after Open in Frame.io) asks for a folder in an Open panel with an "Add to the QCpie queue when downloaded" checkbox (both remembered: `frameioDownloadFolder`, `frameioDownloadAddToQueue`). Links come from `GET …/files/{id}?include=media_links.original` (`download_url`, CloudFront, time-limited; fetched again on 403/404). One connection to the CDN tops out at ~65 MB/s (measured on 2.5 Gbit/s), so files come down as 32 MB `Range` requests from one pool of 8 streams shared by 3 files (measured 245 MB/s avg, 3 GB in 12 s), written at their offsets on their own queue into a hidden `.<job id>.qcpie-download` beside the destination (named by id: long names + prefix could pass 255 bytes) and renamed when complete (cancel / failure removes it). The rename is exclusive (`renamex_np` + `RENAME_EXCL`): `FileManager.moveItem` checks then renames and a rename replaces, so two same-named files (Frame.io allows them) finishing together lost one; taken names get " 2", " 3" (Finder-style). Names with "/" or ":" are made safe. Chunks use a delegate data task (`DownloadEngine.get`): `URLSession.data(for:delegate:)` never calls `didReceive data`, so progress only moved per finished chunk. Files listed without a size come down in one request; free space is checked first; one expired link is refreshed once for all chunks. Listing errors show in the drawer (`lastError`). Quitting while downloading asks, stops and removes partial files (`stopForQuit`, alongside uploads' `pauseForQuit`). Retries share `NetworkRetry` with uploads. Downloaded files join the queue through `ContentView.loadAssets(_:append:)` via the `DownloadQueue.addToQueue` notification, batched 0.6 s. The Mac is kept awake while downloading. `DownloadQueue` is observed only by Upload-tab views. **Pause / Resume** (drawer header): `DownloadResumeState` keeps each file's partial file and the chunks finished in it; Pause sets `isPausing` and cancels the run, so stopped files return `.paused` and keep their partial file (the chunk in flight is fetched again); Resume re-queues them and skips finished chunks (counted with `progress.complete`, not towards the speed). Cancel removes paused partial files too. Not resumable across quits (yet): quitting with paused downloads asks like running ones and removes the partial files (`stopForQuit`). Tests: `Tests/DownloadEngineTests.swift` (`StubCDN`).
- **Right drawer**: `UploadSideDrawer` with Media Info | Downloads | Log tabs (the review sleeve's pill switcher; pages slide in from their tab's side, `forward` set a turn before `uploadDrawerTab` changes so the leaving page's transition matches), resizable from its left edge (`PanelResizeHandle(edge: .leading)`, `uploadDrawerWidth`, 300–800 pt, double-click resets to 360), opened by the chevron at the far right of the Frame.io header (`DrawerTabs`, also a drop target for downloads) or ⌘⇧→ (`toggleRightSleeve`, scope `.playerOrUpload`; spring + slide like the review sleeve; `uploadLogOpen`); a running download shows its percentage by the chevron, and starting one opens Downloads. Only `DrawerTabs` (header) and `DrawerTabBar` (drawer) observe `DownloadQueue` for that: observing it in `FrameIOBrowserView` redrew the browser's list at 5 Hz. Upload and download progress share `TransferProgressCard` (bar, time left, speed graph). **Media Info** is the Player's panel (`MediaInfoPanel` + `MediaInfoLoader`, `MediaInfoPanel.swift`, shared with `NotesDrawerPanelView`; the loader belongs to the drawer so tab switches don't re-read in the Player) for the one selected queue file; the drawer hears `UploadQueue.selection` with `onReceive`, not by observing the queue (its upload progress would redraw the panel), and reads the file only while the page shows. Queue: double-click a file plays it; right-click a folder → Clear Folder (every selected folder when it is one of them, `ContentView.clearFolder`).
- **Log**: the drawer's Log tab (`UploadLogDrawer`, "Transfer Log") shows `TransferLog`: one `UploadLogRun` per upload run and per download batch (`kind`: upload / download; runs saved before downloads were logged decode as uploads), entries added as files finish (a download entry's `.uploaded` outcome means downloaded; paused files aren't logged), saved off the main thread to `upload-log.json` (last 100 finished runs) when a run ends. Each card starts with an UPLOAD / DOWNLOAD pill and has a stripe down its left edge in the same colour (uploads: play accent, downloads: slot B accent); the header filters All / ↑ / ↓ (`transferLogFilter`). Download entries keep `localPath` (right-click: Reveal in Finder, Open, Copy Path), as do download rows in the Downloads tab. The drawer's `tab` is `@AppStorage`, whose writes drop `withAnimation`: the page slide comes from `.animation(_:value: tab)`. `TransferLog` is observed only by the Log drawer, so it doesn't redraw at the queues' 5 Hz.

## 8j. Frame.io Comments ⇄ QC Notes (`FrameIOComments.swift`, `FrameIOCommentPush.swift`)

- **Links** (`FrameIOLinks`, `frameio-links.json`): local clip path → Frame.io account + file id + local size (a file whose size changed is unlinked). Made by QCpie's uploads (`UploadEngine.onUploaded`, single-file clips only: a sequence is many Frame.io files), downloads (`DownloadQueue.finished`), and the browser's right-click **Import Comments into QCpie** (files, folders, stacks → files via `DownloadEngine.expand`, matched to queue clips by name + size).
- **Automatic linking** (the API has no search: `/v4/accounts/{id}/search` is 404): `FrameIOLinks.remember` indexes files by exact "name|size" (stacks: current version) from every folder the browser lists (no extra calls) and from a gentle crawl of the browser's favourites (`crawlFavourites`: 20 s after the first clip opens, then every 30 min; one listing at a time, 0.5 s apart, ≤ 400 folders per pass; nothing while signed out). An unlinked clip opened in the Player is linked from the index (`check`). Listing a folder also links queue clips that match it at once (`linkQueueClips`). Manual: ⌘V in the Player with a file link, or Link from Clipboard in the Notes tab's Frame.io bar (shown when signed in), links the open clip (`linkActive`, warns when the sizes differ).
- **Deleted files**: a 404 for a linked file's comments (deleted here or on the web) unlinks it and drops it from the name/size index (`FrameIOLinks.forget`), so it isn't polled or re-linked.
- **Comments**: `GET …/files/{id}/comments?include=replies,owner` plus a second listing with `timestamp_as_timecode=true` (100/page, 100 calls/min). Frame.io stores the time the browser player was paused at, between frames: `timestamp` is it **rounded**, the timecode Frame.io shows is it **rounded down** (measured, 25 fps: 261 ↔ 00:00:10:11 = frame 261, 450 ↔ 00:00:17:24 = frame 449). Notes use the shown timecode (as frames at the clip's nominal rate, drop-frame handled) minus the file's embedded start (`startFrames`: the largest timecode − timestamp); without a timecode, `timestamp − 1`. Imported notes' frames follow Frame.io on every import. A comment with neither (a still image's, or a video comment not tied to a time) lands on frame 0; PDF page comments (`page`) are skipped.
- **Notes**: purple, author "<name> (Frame.io)" (purple is reserved for these, as red is for Line Check: `QCNoteTheme.frameIOTag`; pickers offer only `availableColors`, `userTag` guards every note written here, and a Frame.io note's colour can't be edited), resolved when completed, replies as replies, ranges and drawings mentioned in the text. Note id = name-based UUID of the comment id (`noteID`), so re-imports and collaborators' imports update the same note (no duplicates through notes sync). `FrameIOCommentImport.merge` = `QCNotesManager.merge` (newer text wins, resolved stays resolved, new replies added), except comments imported before (`imported` per file id) whose note is gone here were deleted here and aren't brought back.
- **When**: the clip shown in the Player (`FrameIOCommentSync.setActive`, from `loadNotesForActiveURL`) is checked when it opens and every 60 s, plus Check Now in the Notes tab's Frame.io bar (shown only for linked clips; `FrameIOCommentsBar` observes only `FrameIOCommentSync`). Its comments go to `ContentView.applyFrameIOComments` (merged into the notes on screen, saved and pushed like an edit, unseen badge when the Notes tab is hidden). Other clips (browser import) are merged on disk. Only Send (below) writes to Frame.io. Network and decoding run on the `FrameIO` actor; nothing runs per frame.
- **Send to Frame.io** (`FrameIOCommentPush`): QC notes written in QCpie become comments (`POST …/files/{id}/comments`, `{"data": {text, timestamp, completed}}`). From the Notes tab's Frame.io bar ("Send N", the open clip) or the browser's right-click **Send QC Notes to Frame.io** (files/folders/stacks → files, matched to queue clips by name + size, `planSend`), always after a confirmation sheet. Stills are sent without a `timestamp` (images refuse one: 422 "filetype does not accept a timestamp", measured on a PNG); a 422 about the timestamp also retries without it. Otherwise `timestamp` is the note's `frameIndex` as an integer: Frame.io shows it at the file's start timecode + timestamp (measured on a 25 fps clip starting at 01:00:00:00: 0 → 01:00:00:00, 51 → 01:00:02:01; a timecode string without the start is a 422), so the importer reads it back on the same frame. Text = note, "— author" when not the signed-in Frame.io user, "↳ author: reply" lines. Never sent: notes imported from Frame.io (by id or "(Frame.io)" author), Line Check markers (author "Line QC": rebuilt with new ids each scan, so they'd be re-sent), notes sent before (`FrameIOLinks.sent`: file id → note id → comment id, recorded per comment as it lands and written to disk at once, so a quit can't lose it and re-send), empty notes. A minute check or Import Comments while a send runs is skipped (its new comments aren't recorded as sent yet and would import as duplicates), the sent record is re-read after each fetch, and a bulk send re-checks it per clip at send time (plans can go stale while the confirmation is open). Over 90 notes: one call per 0.65 s (100/min limit). Goes on after a failed note, stops when signed out.
- **Round trip**: a sent comment comes back on import as an *echo* of its note (`notes(from:fps:sent:)`: the note's id, no text, `.distantPast` date so its text/tag never win, Frame.io's replies, resolved when completed). `merge(…, sent:)` applies echoes only to notes still present (a sent note deleted here stays deleted) and never moves their frame. So client replies and resolving on Frame.io land on the original note.
- Tests: `Tests/FrameIOCommentsTests.swift`, `Tests/FrameIOCommentPushTests.swift` (stub API: never posts).

- **Link index** (`FrameIOLinks`, `frameio-links.json`): read lazily on its actor, never in `init` (`shared` is first touched on the main thread when a clip opens, and the name/size index holds up to 50,000 entries); saves are coalesced to one write a second after the last change (listings and the favourites crawl change it in bursts).
- **Partial downloads** (`.<job>.qcpie-download`, hidden, beside the destination): a normal quit removes them; leftovers from a crash or force quit are swept when a download batch starts (`DownloadEngine.sweepStalePartials`: ≤ 4 levels under the destination, untouched for 6 h, not in use).

## 8j2. Frame.io Preview (`FrameIOPreview.swift`, Space in the Upload tab)

- Space with a file or stack selected in the browser, or double-clicking a file (or a version inside a stack), opens a preview drawn over the browser (`FrameIOPreviewOverlay`); Space or Esc closes; ← → ↑ ↓ move through `visibleItems` (`FrameIOBrowser.reveal` selects and scrolls); clicking another row previews it (the preview watches `selection`). Leaving the Upload tab, navigating the browser (`path` changes) or an emptied selection (the file was deleted) closes it. Router rules `frameioPreview*` (`.uploadOnly`) return false when there's nothing to do, so the key goes on.
- Source: `FrameIO.previewFile` (one GET per open; links are signed and expire), chosen by `media_type`. **Video**: `media_links.efficient` (sharp proxy; may come as `download_url` only, still a range-served MP4 that `AVPlayer` streams), `video_h264_180` instead while an upload or download runs (to leave them the bandwidth). **Image**: `high_quality` (full-size web image; for images `efficient` is a 400 px one), then `thumbnail_high_quality`, then `original.inline_url`. **Audio**: Frame.io makes no audio proxy (all renditions nil, measured on a WAV), so it streams `original.download_url` (range-served, `isPlayable`); badge "Original". Nil links (still processing, restricted project) show a message. A file changed in the last 2 hours (`isRecent`: likely just uploaded) is fetched before the panel opens; with no preview yet it gets a browser toast ("still processing … try again in a minute") instead of an empty panel. Verified: video proxies and the WAV original are `isPlayable` over the network.
- Never the Player: a separate `AVPlayer` + bare `AVPlayerLayer`, so the Player's still-frame architecture (§1) is untouched. The 10 Hz playhead (`PreviewClock`) is observed only by `PreviewTransport`; the browser observes nothing of the preview (its overlay does). The "Proxy W×H" badge says it's not the original: no QC judgments from it.
- Tests: `Tests/FrameIOPreviewTests.swift`.

## 8j3. Bulk Metadata (`FrameIOMetadata.swift`, `FrameIOMetadataSheet.swift`)

- Right-click → **Edit Metadata…** in the browser (inside a project): every selected file (folders: all files in them via `DownloadEngine.expand`; stacks: current version). Fields: `GET …/metadata/field_definitions` with `mutable: true` (Status and Assignee are ordinary fields: select / user_single; system fields like codec or duration are `mutable: false`), ordered Status, Assignee, Rating, then by name. Assignee's choices: `GET …/projects/{id}/users`. Date fields aren't offered yet (no editable one to verify the write format against).
- Each field starts at "No change (current)", the current value read from up to 25 files (`GET …/files/{id}/metadata?show_null=true`; "mixed" when they differ). Only changed fields are sent: `PATCH …/projects/{id}/metadata/values` with `{"data": {"file_ids", "values": [{field_definition_id, value}]}}`, 100 files per call (10 calls/min). Measured formats: selects = option ids, users = `[{id, type: "user"}]`, rating = integer, text = string; clearing = `[]` / `""` / `0` / `false` (`null` is a 422).
- Tests: `Tests/FrameIOMetadataTests.swift` (captured response shapes).

## 8i2. Pre-upload Checks (`UploadPreflight.swift`)

- `UploadQueue.start` (the Upload button and drops onto a Frame.io folder) checks the rows first, in parallel: names already in the target folder with a different size (same name and size is skipped as "already there" anyway; only rows going straight into the folder), files still being written (size or modification time changes over 1.5 s, the last 3 files of a sequence; or a partial-download name: `.part`, `.crdownload`, …), and odd files (no extension, hidden, temporary, or neither media nor a usual deliverable sidecar). Nothing flagged: the upload starts as before. Otherwise a sheet: **Skip These** (Return; uploads the rest), **Upload All**, **Cancel**. The Upload button reads "Checking files…" meanwhile; a drop during the checks says so instead of vanishing. Keep Subfolders is read once, so the checks and the upload agree.
- Tests: `Tests/UploadPreflightTests.swift`.
