# Delivery Plan (Google Sheets)

Inspect's Delivery Plan drawer and window, Sheets sync, matching, statuses and checks.

Section numbers match the old single AGENTS.md, so older commit messages and notes still point to the right place.

## 8e5. Delivery Plan (`DeliveryPlan.swift`, `DeliveryPlanStore*.swift`, `DeliveryPlanPanel*.swift`, `DeliveryPlanRowCard.swift`, `DeliveryPlanControls.swift`, `DeliveryPlanGrid.swift`, `DeliveryPlanSheetView.swift`, `DeliveryPlanQCTab.swift`, `DeliveryPlanOutbox.swift`, `SheetsAPI.swift`, `GoogleAuth.swift`)

- Inspect's right drawer (⌘⇧→, `inspectPlanOpen`) or its own window (`Window` scene `deliveryPlan`, ⌥⌘D, declared after the main window: SwiftUI opens the first `Window` at launch). `deliveryPlanPoppedOut` makes the drawer a placeholder while the window is open. The router passes every key through while the plan window is key (its identifier starts with `deliveryPlan`).
- **Source**: the Sheets API as the signed-in Google user (`SheetsAPI`, `GoogleAuth`). No public link, no Apps Script: the sheet only needs to be shared with the user; Google decides who may edit.
  - **Sign-in** (`GoogleAuth`, `GoogleAccount`, `GoogleSignIn`): OAuth + PKCE through `ASWebAuthenticationSession`, iOS-type client (`AppConfig.googleClientID`, no secret, redirect `<reversed client id>:/oauth2redirect`), scopes `openid email …/auth/spreadsheets`. The client lives in the studio's Workspace Cloud project with an **Internal** consent screen: studio accounts only, no verification, refresh tokens don't expire after 7 days (they do for External apps left in Testing). Tokens in `Application Support/QCpie/Google/tokens.json` (0600, not the Keychain: ad-hoc signing). Only 400/401 from the token endpoint signs out; a Google 5xx or being offline keeps the tokens. Empty client id: sign-in is off.
  - **Calls**: `metadata` (title, tabs: hidden tabs and the QCpie tab aren't plan tabs), `values` (`values:batchGet`, FORMATTED_VALUE, every included tab plus the QCpie tab in one call; the raw reply is compared with the last one, so an unchanged sheet isn't parsed), `layout` (formatting, see Views), `validations` (dropdowns), `update` (RAW = text as given, else as if typed), `append` (INSERT_ROWS), `clear`, `batchUpdate`. 401 → one forced token refresh; 403 = no access, 404 = not found/not shared, 429/5xx transient. The user agent says "gzip" (Google gzips only then). `+` in ranges is percent-encoded (Google reads it as a space). Sheets API quota: 60 reads/min per user; the plan uses ~6.
- **Parsing** (`PlanParser`): header row = first of the top 40 naming a file-name column + 2 other known columns (`PlanField.detect`, by header text, any order). Rows without a name are skipped, a lone text cell is a section title, a lone number a subtotal, a row named Total / Grand total is skipped; with an ID column ("Code"), a row without an ID is a heading (text) or a total, unless it has specs (resolution, aspect, size or format): then it's a deliverable without a code yet and still shows. Values: resolution, aspect, length (`30s`, `2-3s`, `1:30`, `30s / 15s`), size cap (decimal MB), format (from Format, or a codec in the size column, `gif` in Length/name), fps. Sheet contradictions are `issues` (resolution vs aspect, `_6s` name vs 10s length, duplicates). Row identity: the ID column, else tab + name + channel + placement + resolution + aspect + logos + subs + translations + format (+ occurrence).
- **Tabs**: linking turns on one tab (the link's gid, else the most coded rows, then the most rows, `startingTab`: sheets list the same files twice, by placement and by edit, and the edit tab often has more rows but no Code column, so it can't take statuses or links); the picker under the title shows row counts. The QCpie tab is never in the picker (it holds tracking, not deliverables).
- **Live**: values every 10 s while a plan panel (or Inspect) is on screen, every 60 s while QCpie isn't the active app (`panelAppeared`/`Disappeared`); parsed, matched and redrawn only when the reply changed. The tab list every 3 min, on sign-in, and when a range fails (400: a tab renamed or deleted). `phase` and `lastUpdated` publish only on change (at most once a minute when nothing changed): each publish redraws the panels. Changes are against a "seen" snapshot (`seen.json`, Application Support/QCpie/DeliveryPlan/<sheet id>, plus `values.json`, the last values shown before the first read): new / changed (field: old → new) / removed until Mark Seen.
- **Matching** (`PlanMatcher`, off the main thread, only when rows or files change): Inspect's measured assets (`setAssets` from `ContentView` on `specsState.assetsVersion`). A file's candidates are the rows whose whole name is the longest run of its name tokens (an ID column value wins alone; when the file's name doesn't contain that row's name, the row gets "The file name doesn't match KLnnnn's row (the name looks like row N): check the code."), looked up by name (`byName`; a name ending in its own ID is indexed without it too, so files named without the code still match). Mock deliveries for trying it: `_TEST/DeliveryPlanMock` (97 tiny files + `_ANSWER_KEY.csv`), `_TEST/DeliveryPlanMock_v3` (152 rows of the v2 plan with a Batch column, 151 files in batch / edit / channel folders, a few wrong-spec, missing, no-code, duplicate and extra cases; `_PLAN.csv` is the sheet to import). Among them: fewest spec problems, then name hints (clean/logo, an aspect like `9x16`), then rows not yet taken. Perfect fits are placed first; a file whose best rows already hold perfect fits is an extra with its closest row. Look-alike rows left empty get "Could also be row N". 1,117 rows × 1,117 files: ~1 s in a debug build.
- **Views** (`deliveryPlanView`): **Sheet** (default) draws the shown tab as Google Sheets does, from the API's grid data (`SheetsAPI.layout` → `PlanGrid.fromSheets`: column widths, row heights, frozen rows, effective formats — fill, text colour, bold/italic/underline/strike, alignment, wrap, borders — merges; hidden rows and columns left out, `sheetColumns` maps view → sheet columns). The layout is large (~1–3 MB per 1,000-row tab), so it's read only on link, every 5 min and when the values table changed size (`fits`), one tab at a time at `.utility`, cached in `layouts.json`; every values read fills it (`withTexts`). Conditional formatting follows values (a status recolours its cell), so after a read that changed some rows of a same-size tab, only those rows' formats are read again (`SheetsAPI.rowFormats`, `PlanGrid.changedLines` / `patchingFormats`, a few KB; more than 40 changed ranges → the whole layout). Until a layout is read, `PlanGrid.fromTable` (no formatting). Drawn in AppKit (`PlanSheetContainer`: column letters + frozen rows, row-number gutter with QCpie's status dot and changed bar, body in an `NSScrollView`; each part draws only its visible rows, the header and gutter redraw on scroll). Cells keep the sheet's own colours in both modes; the chrome uses the palette. Filters hide rows (frozen rows stay); several read tabs get Sheets-style tabs below; the selected row's card (`PlanRowView`) shows under the grid; right-click → Show in Inspect / Play / Reveal / Copy File Name / Open Row in Google Sheets (`webURL(tab:line:)`). Zoom `deliveryPlanZoom` (75–150 %; CSS px = points, fonts pt × 4/3). **List** is the per-deliverable card view. The cache is rewritten only when the values changed.
- **Editing**: needs Google sign-in (`canEdit`). In the Sheet view double-click a cell to edit (Return / click away saves, Esc cancels: in the main window the router ends editing, so Esc is read from `NSApp.currentEvent`; Tab saves and edits the next cell); double-clicking the row number plays. A typed cell in one of QCpie's columns goes to the QCpie tab by code; any other goes to the outbox as a `Cell` carrying the row's code, the column's header and the text QCpie showed (`expect`). On send each tab is read and the cell found again (`locate`: row by code when sorted, column by header when moved) and written (USER_ENTERED) only if it still shows `expect`, else refused with its current text. The Sheets API has no compare-and-swap: the check and the write are ~1 s apart. The pop-out flag is reset at launch and cleared by Dock even when the window isn't open.
- **QCpie tab** (`PlanQCTab`, `DeliveryPlanQCTab.swift`): QC Status, QC Note, QC Updated, Batch, Frame.io, Uploaded live in one tab named "QCpie", one row per code (columns by header; Code must stay in column A). It's the only place they're written, so a code listed on several tabs can't disagree (nothing copies between tabs any more). Plan tabs show them as lookups: one `ARRAYFORMULA(VLOOKUP(code&"", 'QCpie'!$A:$Z, MATCH(header…)))` per column (`PlanQCTab.formula`), no dropdown, a warning-only protected range. Rows read take their tracking values from the QCpie tab (`PlanRow.withTracking`); without the tab (an old sheet), the plan tabs' own columns are read and writes wait. Clients can see the tab (sharing is per spreadsheet).
  - **Set Up QCpie Tab…** (••• menu, status line; `setUpQCTab`, `PlanQCTabSetupSheet` says what changes first): reads every tab, builds the tab's rows (`qcTabPlan`: per code, QC fields from the row with the newest QC Updated, others from the first row that has them, outbox edits win) and sends **one atomic `batchUpdate`** (`qcTabRequests`): `addSheet` (gid picked by QCpie, 26 columns: the lookups read A:Z), its values as `stringValue` (text stays text), bold header, QC Status dropdown, and for each plan tab's QC column an `updateCells` over the column below the header (formula in the first cell, the rest and its dropdown cleared) plus `addProtectedRange` (warningOnly). All or nothing: a failure can't leave columns cleared without the tab holding their values.
  - **Edited in Sheets**: a QC Status changed on the QCpie tab without a new QC Updated is stamped "… UTC · Sheets" by the first Mac that reads it (`stampSheetsEdits`; quiet outbox write).
- **Outbox** (`PlanOutbox`, `outbox.json` in the plan's folder, written in order off the main thread): every write — statuses, notes, batches, Frame.io links and stamps (`Record` by code, fields merged, `quiet` for automatic ones) and typed cells (`Cell`). Its contents are laid over the rows and grids (`overlay`, `cellOverlay`), so edits show at once. `flush` (0.3 s after the last change, on sign-in, after each read when anything is unsent, at launch): reads the QCpie tab (rows may have moved), writes values for known codes in place (every line of a duplicated code) and appends new codes (`PlanQCTab.writes`, RAW), puts a cleared header back, adds missing columns. Google took it → `written`; it leaves the overlay once a read that **started after** that comes back (`settle`), so nothing flicks back and nothing expires. A record changed while being sent isn't marked written (sent again). Signed out / no QCpie tab: kept, said once ("Saved on this Mac…"). Offline, 429, 5xx: kept, retried with backoff 5 → 120 s. 400: tab list re-read, kept. 403/404: dropped with the reason (quiet ones silently). Already-written edits are never dropped by a refusal (a read will show them). A flush that changed nothing (offline retry) doesn't save, recompute or re-read. Relinking the same sheet keeps the outbox; linking a sheet loads its saved one. Applies are generation-checked (`applyGeneration`): the disk cache never overwrites a newer read. Sign-in: a token refresh that finishes after a sign-out or a new sign-in is discarded (`GoogleAuth.generation`). Survives quitting. Replaces the script's pending/sent/expiry/deferred/version-gate machinery.
- **Changed meanwhile** (`PlanOutbox.Record.expect`, `conflicts(with:)`, `discard`): a hand edit of QC Status, QC Note or Batch keeps what QCpie showed (the first edit's while unsent; optional on disk). On `flush`, a field the QCpie tab now shows as neither that nor the new value was changed by someone else: it isn't written (QC Updated goes with a refused status), leaves the outbox so the sheet's value shows, and the reason is reported ("KL0420's QC Status was changed in the sheet meanwhile (now “Approved”)"); the record's other fields are still sent. Automatic writes (links, stamps) carry no `expect`. Same ~1 s check-to-write gap as typed cells.
- **Lost Code column** (`codelessTabs`): a tab read with a header but no Code column, in a sheet with the QCpie tab, is named in amber under the filter bar (its rows can't show or take statuses).
- **QC statuses** (Phase 1A). One state per row (`PlanState`):
  - Automatic: Missing / To QC / Check, from the match. Check covers both a spec that doesn't match (`PlanStatus.wrongSpec`) and an unsure match (look-alike rows, two files for one row); the row's problems and flags say which. Manual: Needs Fix, QC Passed, Approved, Delivered, On Hold, Dropped (8 states in all).
  - Manual: `PlanQCStatus` (Needs Fix, QC Passed, Approved, Delivered, On Hold, Dropped), read from the sheet's QC Status column, which wins.
  - `PlanStatusResolver.resolve`: a matched file modified after QC Updated ("yyyy-MM-dd HH:mm:ss UTC · reviewer"; stamps without "UTC" are older and local time) sends the row back to To QC with a flag (works across machines: copies keep their modification date).
  - QC Status / QC Note / QC Updated are `PlanField.isQC`: never part of row identity, "changed" highlights or `matchSignature`, so a status edit doesn't re-run matching.
  - Only status changes are stamped (a note edit must not hide a new version that arrived before it).
  - Dropdowns: `validations` of the row under each tab's header (`parseValidations`: ONE_OF_LIST values, ONE_OF_RANGE ranges read in one `values` call), keyed by header text (lower case; `#sheet column` without one), read with the layout. `listColumns(gid:)` maps them onto the Sheet view's columns by header text. Dropdowns (menu and ▾) apply only below the header line. Double-clicking such a cell opens a menu of its choices (plus Clear) that writes through `editCell`; QC Status keeps its own menu.
  - Store:
    - `setStatus` / `setNote` / `setBatch` and Frame.io links go through `queueQC` → the outbox (shown at once, gathered for 0.3 s into one call).
    - Inspect being open counts as a visible panel; a return within 60 s of the last read skips the full read.
    - `setAssets` keeps the modification dates read for the same inspection (`assetIDs`: `DeliverableAsset.id` per file). Inspect's per-file loudness and end-frame updates stat only new or re-read files, not all 1,000+ each time. The plan's List items are built only in List view.
  - Status from: the row card's status menu, right-click Set Status (sheet and list; applies to every Inspect-highlighted row when the clicked row is one of them), double-clicking a QC Status cell (menu), Inspect's right-click Set Plan Status (selection), and ⌥1–⌥6 / ⌥0 clear: router rule `planStatus` (`.specsOnly`) on Inspect's selection else `focusedRowID`; hidden buttons in the plan window. Chips are states with a "% done" figure (QC Passed + Approved + Delivered of all not Dropped).
  - **Inspect:** `ContentView.planFiles` mirrors `DeliveryPlanStore.fileIndex` (code, row, state per file; changes only when it does). It feeds:
    - `PlanPill` in the name cell.
    - `SpecsRowKey.plan`, so only changed rows redraw.
    - The plan's chips above the table (`inspectPlanChips`, the shared `PlanFilterChip`: % done, All, one per state with file counts, Not in Plan → `inspectPlanFilter`).
    - Plan sorting (header right-click → Sort By → Plan Order / Plan Status → `inspectPlanSort`, stable over the column sort; clicking a column header turns it off).
    - Code search.

    `inspectPlanFilter` and `inspectPlanSort` are part of `displayedAssets`' cache key; the closures only run on a cache miss.
- **Linking rules are pure** (`DeliveryPlanStore.linkDecisions`): `frameIOListed` only feeds it and acts on its answers. `Tests/DeliveryPlanFixtureTests.swift` runs a test plan (`_TEST/DeliveryPlanMock/_PLAN.csv`; placeholder data, the real naming isn't final: replace the plan, files and answer key as it changes) and the mock delivery's names as a listing against `_ANSWER_KEY.csv` (local, git-ignored; skipped without it): 50 ok + 27 wrong-spec files link to their own rows, duplicates are suggested, extras and code-less names never link by themselves. Change a rule → run it and see which links move.
- **Suggested links** (`LinkSuggestion`, `PlanSuggestionsButton` → `PlanLinkSuggestionsSheet`, `DeliveryPlanSuggestions.swift`): a listing links a row by itself only when certain: one file for the code, its name holding the code **and** the row's name. Every other rule (found by name alone, a stripped code, the local file's name, one of several files for a code) becomes a suggestion (one per code, in memory, rebuilt by the next listing or folder read) shown as "N Suggested" at the end of the filter bar, with Accept / Accept All (→ `queueQC`, like a hand link) and × (dismissed for good: key "sx|code|file id" in `dismissedMismatches`). A row that gets a link any other way leaves the list (`queueQC`).
- **Frame.io folder** (`Config.frameioRoot`, `FrameIORoot`: account + listed folder + "Project › Folder"; `PlanFrameIORootSheet`, ••• → Set Frame.io Folder… / health popover's Frame.io row): the project or folder holding the plan's files, picked from the Upload tab's open folder or a pasted project/folder/file link (`frameIORoot(fromLink:)` → `FrameIOLink.resolve`). Once set, only its tree is the plan's: `frameIOListed` ignores listings outside it (`inPlanTree`), `recordListing` keeps every folder of it (not only those holding plan files), and extras come from all of them. `runRootScan` lists it breadth-first (0.4 s apart, ≤ 1,000 folders, through `FrameIOLinks.remember` like a browsed listing) when set, when a plan panel opens and every 15 min while one is open, and from ••• → Read Frame.io Folder Now (`findFrameIOLinks`); a complete scan replaces the tree (`frameio-tree.json`) and drops listings of folders no longer in it. `rootScan` publishes at start, end and every 10 folders. Without a folder, the old behaviour (browsed folders holding plan files, favourites crawl) stays.
- **Setup guide** (`PlanSetupGuide`, `DeliveryPlanSetupGuide.swift`): sign in → link the sheet → add the QCpie tab → choose the Frame.io folder (optional), each step ✓ with what was chosen or its one action, later steps dimmed until possible. Inline in the panel before a sheet is linked (and while relinking); as a sheet from ••• → Set Up Plan… and right after linking while steps remain.
- **Undo** (`undoLastEdit`, `undoTitle`): the last hand edit through `queueQC` (status, note, batch, Frame.io link; not automatic writes, not typed cells) keeps each code's previous values; ⌘Z in Inspect (router rule `planUndo`, returns false when there's nothing) or the plan window (hidden button), or "Undo Status" next to "Saved", writes them back without a new stamp. One level.
- **Filters menu** (`PlanFiltersMenu` + `PlanActiveFilterChip`, `DeliveryPlanFilters.swift`): batch, Frame.io presence and mismatch filters in one menu (sections with counts, Show Dismissed, Clear Filters), labelled "Filters" with an amber mismatch count; each filter that's on shows as a chip with × (batch, Frame.io/mismatch, channel). Same in the plan and Inspect (Inspect's mismatch kinds: those a local file can have). Replaces the separate Batch, Frame.io and mismatch menus.
- **Reading less** (`SheetsAPI.version`, scope `drive.metadata.readonly`): before the 10 s values read, the sheet's Drive version (a few bytes); unchanged → no read (at most 3 min apart). Needs the Drive API enabled in the Cloud project and a sign-in after the scope was added; a 403/404 turns the check off for 30 min (`versionCheck`), and the plan reads the values as before. A 429 doubles the poll interval up to ×12 (`readBackoff`) until a read succeeds; the badge says Google is busy.
- **Connection health** (`DeliveryPlanHealth.swift`): `PlanHealthBadge` by the plan's title, one dot and a word for the most pressing state (`PlanHealth.status`: Signed out › Can't read › View only › No QCpie tab › N waiting (retrying) › Not saved › Saving N › Synced). Its popover lists Google account, Reading (last read or the error, Read Now), Writing (Try Again → `retrySending`), QCpie tab (Set Up…) and Waiting (to send / sent and confirming). `store.health` is set where those change (`noteOutbox` from every `saveOutbox`, read success/failure, each flush outcome; `canWrite` false on a 403 write, reset on sign-in) and publishes only on change.
- **Summary view** (`DeliveryPlanSummary.swift`, the first segment of the plan's view picker, `deliveryPlanView = "summary"`): % done with one bar of every state (`PlanStateBar`, `PlanSummary.barOrder`: done, in hand, to arrive; dropped left out), headline figures (To Arrive, In QC, Needs Fix, Done, Today = statuses set in the last 24 h), then sections in an adaptive grid (one column in the drawer, two or more in the window): Status, Batches, Channels (≥ 2), Frame.io (presence + each mismatch kind, amber), Recent Reviews (the 8 newest QC Updated stamps). Every row, single-state figure and bar segment opens its rows (In QC and Done span several states, which the one-state filter can't show: they only explain themselves): `openFromSummary` clears the filters, sets the one clicked (state, batch, upload/mismatch, channel — a removable chip in the filter bar, `channelFilter` — or selects a row) and switches to the last Sheet/List view (`deliveryPlanDataView`). The filter bar and search hide in Summary. Figures come from `PlanSummary.build` (~1 ms for 1,100 rows), cached by `PlanSummaryCache` on `store.statesRevision` (bumped by every `recomputeStates` and by `resetState`) plus the hour (so Today rolls over); reviews are ranked by their UTC stamp text and only the newest 8 parsed (a parse per row cost ~10 ms per status change); a code on several tabs is one review; Frame.io counts include dropped rows, as the filter does; `PlanSummaryView` is `.equatable()`: redraws (each Inspect selection) cost nothing; no reads of its own.
- **Columns in the Sheet view vs the sheet**: the view leaves hidden columns out, so sheet column numbers (`headers`) don't always line up with it (`PlanGrid.sheetColumns` maps them). Anything drawn or edited in the view finds its column by header text: `gridColumn(_:gid:)` (pending-write overlay, QC Status menu), `listColumns(gid:)` (dropdowns).
- **Batches** (`PlanBatch`, `PlanField.batch`): a Batch column of whole numbers ("1", "2", "3"…; sorted by number, 2 < 10; other text sorts last; New Batch… accepts only whole numbers). Batch and the QC columns are `isTracking`: never part of row identity, matching or "changed". Set from the plan (right-click / row card / status bar: Set Batch ▸ batches, New Batch… (`askNewBatch`, offers the next number), Clear Batch) or Inspect (Set Plan Batch); written with the statuses (QCpie tab, outbox; as text: RAW / `stringValue`). `store.batches` (natural order) feeds `PlanBatchFilter`, a filter-bar menu with each batch's count and % done, in the plan's and Inspect's chip rows (`batchFilter` / `inspectPlanBatch`, part of `SharedFilter` and of `displayedAssets`' plan key). `PlanFileInfo.batch` carries it to Inspect.
- **Frame.io column** (`PlanField.frameio` / `.uploaded`, both `isTracking`; written with the statuses to the QCpie tab through the outbox). The sheet holds the link as plain URL text (Frame.io's `view_url`, project members only), so every machine reads it from the sheet. Filled by:
  - **Uploads** (Upload tab only; QCpie has no second upload path): `UploadEngine.onUploaded` → `DeliveryPlanStore.uploaded` (not awaited by the upload) finds the row by the file's plan match, else by a code in its name (exactly one), fetches the file's `view_url` (one GET) and writes it plus Uploaded = now ("yyyy-MM-dd HH:mm UTC"). A new upload replaces the row's link.
  - **Listings** (browser and favourites crawl, via `FrameIOLinks.remember` → `frameIOListed`): a row with no link gets the listed file whose name holds its code, only when exactly one file in that listing does (stacks: the stack's link, which survives new versions), only into a sheet with the QCpie tab, never over an existing link, and only when the file's name also holds the row's name or equals its matched local file's (codes repeat across campaigns; a code alone could link another project's file). Files without a code in their name link when their name is exactly the local file matched to a row (checked first) or a row's name without its code (`strippingCode`), only when that points to one row (`exactNameIndex`: `local` and `bare` kept apart, built per rows / match revision). Several files for one code (a `_v2` beside the original) link only the one named exactly like the row. Checked on the 97 mock files: 81 linked by code, plus the 4 duplicates' originals and the no-code files (2 by name alone, 2 more need their local match). One recompute per listing (`queueQC(refresh: false)`). Codes are looked up through `codeIndex` (first code token → codes, rebuilt when `rows` changes), not per row.
  - **Find Frame.io Links** (plan ••• menu, with the QCpie tab): `findFrameIOLinks()` runs the favourites scan now (`FrameIOCommentSync.scanNow(projects:)`), plus the root of every project the plan's links already point to, instead of waiting for the 30-minute scan; listings link rows by the rules above. It reports "Found N links" / "No new links" in the status line for 8 s (`linkSearch`). One scan at a time (`crawling`): while the background scan runs it says so.
  - **By hand**: Link Frame.io File… / Change… / Clear (plan menus, Inspect right-click), `PlanFrameIOLinker` (prefills a Frame.io link from the clipboard; `FrameIOLink.parse` + one GET per account).
  - **Gone**: files or stacks deleted in QCpie's browser, or found gone (`FrameIOLinks.forget`), clear the rows linked to them.
  **Uploads outside the plan's matched files** link only when the file name holds the row's name too (codes repeat across campaigns). An edit queued while a send is in flight is sent again (`PlanOutbox.written` compares `changed` with the send's start).
  **Stacks**: Uploaded for a stack is its last change (`listedDate`: `updated_at`), and a listing showing a linked stack changed since moves it on, so a newer version on Frame.io isn't read as Frame.io being older. The early-upload warning applies only to rows with a local file here (or Needs Fix): a Mac without the files shows linked rows as Missing, not uploaded too early. Uploads' links are queued with one recompute per burst (`scheduleRecompute`).
  Batch, Frame.io and Uploaded are written as text (RAW): "2026-11-05 10:42 UTC" mustn't become a date. Filter menus stay visible while their filter is on (a linked filter could otherwise hide rows with no visible cause). Filter counts are built once per state recompute (`planCounts`) and, in Inspect, once per file / index change (`InspectPlanCounts`).
  **Upload state** (`PlanRowState.upload`, `PlanUpload`): none / uploaded (the row has a link) / stale (a matched local file was modified more than a minute after the Uploaded stamp: Frame.io has an older version). Flags on the card: "Changed after its upload…" and "On Frame.io before passing QC" (linked but not QC Passed / Approved / Delivered / Dropped / On Hold). `PlanUploadFilter` (All / On Frame.io / Not on Frame.io / Changed Since Upload, amber dot when any are stale) sits in both chip rows (`uploadFilter` / `inspectPlanUpload`, part of `SharedFilter` and Inspect's plan key); a small arrow by the gutter dot (amber when stale; gutter 58 pt) and an arrow on `PlanPill`. The template's Summary counts "On Frame.io" overall and per batch (non-empty Frame.io cells).
  Shown as "On Frame.io" on the row card and Open in Frame.io / Copy Frame.io Link in the menus; `PlanFileInfo.frameio` carries it to Inspect. Checked against a real project: 89 of 97 mock files matched one code each, the 8 without a code in their name need Link….
- **Several Macs**: each signs in with its own Google account; nothing to share between them. A refused edit (`editState` `.failed`) shows as a toast while Inspect is the tab (`ContentView`), since the plan's status line may be closed.
- **Dismissing mismatches** (`dismissedMismatches`, per plan in `dismissed-mismatches.json`): rows by `mismatchKey` (row id, kind, linked Frame.io id, and for "another version" the newest local file's date), so a flag comes back when what it was about changes; files by "fx|<Frame.io id>" / "lx|<path>". From the row menus (Dismiss Mismatch, also Inspect's right-click), each "not in the plan" file's × or right-click, and Dismiss All on those lists. Dismissed ones leave the counts, flags, arrows and lists (`localExtras` is `match.extras` without them); the mismatch menu's Show Dismissed (N) (or right-click In Sync) brings all back (`planCounts.dismissed` counts the ones that would show now).
- **Bottom drawer** under the Sheet view (row card, not-in-the-plan lists): `PlanBottomDrawer`, top edge drags its height (80–700, `@AppStorage("planDrawerHeight")`, double-click → 180); it owns the height so a drag redraws only the drawer.

- **Robustness notes (review rounds):**
  - **Store:** each tab's values are parsed once per read (`PlanParser.parse` returns rows and header). Linking or unlinking resets everything read from the old sheet (`resetState`), the outbox included (unlink deletes its folder).
  - **Check queue:** Stop also clears Pause. `checks.json` keeps the newest 3,000 results.
  - **Cell editor:** it follows its cell across re-layouts (`repositionEditor`; it saves and closes if the row is no longer shown). It hands focus back to the sheet only when a key ended the edit.
  - **QC note field:** text typed for one row is saved to that row when the selection moves (`noteRowID`).
  - **Check results are stamped with the size and date the plan sees** (`Job.size` / `modified`). An image sequence's size is the whole sequence; stamped with its first frame's own size, a sequence never matched and was re-checked every run.
  - **Sheet double-click without editing set up** plays the row's file. It doesn't open the set-up sheet; that's in the ••• menu.
  - **Double- before single-tap:** "Not in the Plan" entries attach the double-tap first, or it never fires.
  - **Selection lookups:** the plan's highlighted rows come from the file → row index. Inspect's plan menu items look up the selection's rows only when chosen, through sets.
