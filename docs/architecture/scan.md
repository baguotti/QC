# Scan and analysis: Line Check, Frame Check, loudness, legal range

Detectors and their benchmarks. Every detector change is benchmarked before and after.

Section numbers match the old single AGENTS.md, so older commit messages and notes still point to the right place.

## 8d. Scan tab → Line Check (`EdgeDetector.swift`, `VideoScanner.swift`)

- **Benchmark before and after every detector change**: `scripts/LineFinderBench/run.sh` (Command Line Tools only; the swift-testing suite needs Xcode). It runs the synthetic v1/v2 cases (`Tests/LineFinderScenes.swift`, shared with `LineDetectorTests`), per-frame cost, and real-footage ground truth from `_TEST` (local, git-ignored). It must print ALL PASSED.
- **Colour rule**: a pixel is the target only if its residual is within `colorResidualRatio` (0.5) of the line's own strength α·|T − R| (or the noise floor). The old loose rule (0.3·|T − R|) let grey columns pass as green and green lines as white; lines passing only the loose rule are **off-colour**: reported separately, always weak (persistence-gated), toggle `reportOffColorLines`.
- **Split seams**: compared with the picture 2 px and `edgeDepth + 1` px away; a seam pixel needs a strict match on one side and a loose match on the other (a blended seam's base belongs to one side). A coarse pre-check (every 8th sample) skips rows/columns that can't hold a seam (11.5 → ~2 ms/frame at 1080p). Black/white targets need α ≥ 0.6 for seams: partial dark/bright seams are indistinguishable from window frames and table edges.
- **Letterbox / pillarbox**: when an edge has a uniform near-black bar thicker than `edgeDepth`, the picture edge inside the bar is scanned too (not for a black target); `LineDetection.position` holds the bar depth (edges) or the seam row/column (splits, buffer coordinates). A band found there must be brighter than the bar (luma > 36, `matteLineLuma`): on a dark backdrop (luma ≤ 24 reads as a bar) the rows beside a title or product are the backdrop, not a line (Kiko Holiday 1:1: a 10 px "top line" 77 px down).
- Frame numbers come from sample timestamps rounded to the nearest frame (`VideoScanner.frameIndex`), not from counting decoded samples: the Player seeks to frame centres, so frame n is the n-th sample, and on a 600 time base (QuickTime, iPhone) NTSC-rate timestamps sit up to half a tick early, where `floor` lands one frame low. Timecodes stay 0-based NDF like the rest of the app.
- A file that can't be opened or stops decoding early is never clean: `VideoQCResult.readError` / `FrameCheckResult.readError` flag it (lines found before the failure are kept) and the results and reports show it as Unreadable.
- **Chroma bleed**: a line must step back to the picture one row inside it (inner α ≤ 0.6 × the innermost line row's α,
  so gradients are rejected). When that row mostly fails only on colour (α in range, residual too large), it is the line's
  4:2:0 chroma smeared by the decoder (Premiere renders a 1 px top line's next row as `0,129,1`, not a blend; AVFoundation
  smears a 3 px line at an odd column into a half off-colour 4th column) and the step is checked one row further in.
  Off-colour pixels count as colour failures here. Gradient rows still pass as blends, so they're unaffected.
  `premiere/linecore` mirrors `EdgeDetector.swift` exactly: change both and run `premiere/linecore/tests/run.sh`.
- Edge lines must start within `edgeDepth`; when a band fills the whole scan depth it is followed `thickLineMargin` (16) px further to find where it stops, so lines as thick as the edge depth are caught. That second pass runs only in that case.
- **Solid bars** (`solidBar`): a target-coloured band thicker than that is invisible to those passes (their reference, just past the scan depth, is still inside the band). When the innermost scanned row is ≥ 90 % within 100 of the target colour, the edge is scanned again up to 8 % of the frame; the band must reach α ≥ 0.6 over ≥ 90 % of the edge. Coloured targets only (black bands are letterboxing). Found in Premiere: a 34 px green bar at 1080p under subtitles. Foliage, a partial-width bar and a green wall past 8 % stay clean (`LineFinderScenes`).
- **Throughput is hardware-decode bound** (measured, M4 Max 1080p H.264: one decode stream ~950 fps, two ~1,780, more add nothing; detection ~0.1–1.3 ms/frame overlaps fully). Files run two at a time and a file ≥ 20 s is read as **two segments in parallel** (`VideoScanner.splitMinimumSeconds`): each segment reads 3 frames past the split and keeps only its side, frame numbers count from the first segment's first sample, so results are identical to one pass (verified on `_TEST`: all 204 flagged frames). Machines with two decode engines (M1/M2 Ultra) scan roughly twice as fast.


- **Not a Line** (`LineCheckDismissals`, `ScannerState.swift`): a finding dismissed in the results is stored per clip (file name + frame count: no disk reads) as edge + frame range and removed (±2 frames) from every later scan of that clip before Finder tags, reports, notifications and Player markers see it (`VideoQCResult.removingDetections`). `ScannerState` keeps the raw results so Restore (card header, or Restore All above the cards for clips whose findings are all hidden) brings them back. Completed files are filtered one at a time (refiltering everything per file was O(n²)).

- **Player line marks** (`VideoViewportView.updateLineMarks`, toggle `PlayerEngine.showLineMarks`, `prefShowLineMarks`, button shown only for clips with findings): `setScanResults` keeps each clip's `errorFrames` by frame (`PlayerEngine.lineMarks`, not published) and the viewport outlines that frame's detections with bordered `CALayer`s, sublayers of `stillFrameLayerA/B` like the zebra. **Paused only**, no decode: rects come from thickness / position (`lineMarkRects`, buffer size from `resolution`, swapped when the on-screen orientation differs), rebuilt only when the frame's lines, the still's size or the zoom change; border and padding are divided by the canvas zoom so they stay a hairline. The outline colour is picked per mark (`LineMarkColor`): red unless it is close to the line's colour or to the picture around it (mean of a 32 px copy of the paused still, made off the main thread 80 ms after stepping settles: marks are drawn at once in the last colours, so a held arrow key never pays for it), then the furthest of yellow, cyan, magenta, white.
- **Inspect follows the queue through one call** (`SpecsState.queueChanged`: `.replaced`, `.added`, `.inspectOpened`; `ContentView.inspectFollowsQueue`). While Inspect is shown files are read at once (8 at a time); on other tabs the list is left alone and `prewarm` reads details one file at a time at `.utility`, never while the Player plays or scrubs, into `mediaInfoCache` (shared with Media Info through `details(for:)` / `cachedDetails(for:)`). Opening Inspect lists cached files without a second read and reads only the rest. Media Info must never append to `deliverableAssets` (a list holding one clip read as "already inspected": 0.15.15). Cached details carry the file's size and date from just before the read (`cacheStamps`): Media Info and Inspect's first open check them off the main thread and read a clip again when it was re-exported at the same path since (the cache can be minutes old); the Player's zebra mask is keyed by the file's date for the same reason.

## 8e. Scan tab → Frame Check (`FrameCheck.swift`)

- One decode pass per video finds three things: **frame-rate mismatch** (stutter), **flash frames** and **Media Offline** frames. Results list only flagged files, one row per finding.
- **Benchmark**: `scripts/FrameCheckBench/run.sh` renders clips with known conversions (24→25 repeats, 25→24 / 30→25 skips, 3:2 pulldown, 24→25 blending), flash frames (black mid-shot, white at a cut, 2-frame solid colour), Media Offline cards (strokes for text, real words, ten lines of small text, a single frame, Premiere's red gradient, a graded blue-grey card for one frame, held, and at the segment split), stray pictures (1 and 2 frames mid-shot), and clean controls (hold + cut, static, one-off repeat, dip to black with black head/tail, orange/magenta graphics, a red end card with a white title, shaded moving red footage, a plain red hold, a camera flash, a 1-frame shot between two shots); then it reports the `_TEST` clips. Must print ALL PASSED. Real ground truth: CK_HOME26 E3.0 (25 fps) = 23.976 → 25 (1 repeat every 24 frames); everything else in `_TEST` is clean.
- Same parallelism as Line Check: two files at a time, files ≥ 20 s split into two segments (the second starts 3 frames early so kept frames have their neighbours for motion, blend and shift); results identical to one pass.
- Decode is hardware-scaled to 192 px 4:2:0 (luma + CbCr planes), ~600–3000 fps. Per frame: **motion** (90th-percentile 8×8 block difference: a repeat reads ≤ 0.2), **speed** (region brightness-profile shift in px; a skip reads ~2×), **blend ratio**, and a **look** (luma/chroma p2–p98 spread, mean colour, share of offline-card red).
- **Mismatch only**: repeats/skips count only as a regular cadence (≥ 4 events, ≥ 60% regular spacing); blends only as a cycle (detrended autocorrelation ≥ 0.7 at P, ≤ −0.5 at P/2). One-off repeats/skips/blends are not reported. Repeat bar: ≤ max(0.35, 0.08 × local motion).
- **Flash frame**: 1–2 solid frames (spread ≤ 12; up to fps/12.5 frames at high rates) with a picture (spread ≥ 30) on both sides. Head/tail black, holds and dips to black are not flash frames.
- **Stray frames** (`StrayFrames`, `FrameCheckAnalyzer.strayFrames`; reported with the flash frames as "Stray picture"): 1–2 frames (a few more at high frame rates) of another picture inside a shot, whatever they show. Measured only where a jump (motion ≥ `cutMinimum`) follows a jump 1–4 frames back, from the last twelve 192 px luma images, by correlation: the shot carries on after them as it did before (`continuity` ≥ `expected` − 0.1, `expected` = the shot's own correlation over the same distance just before), the shot is steady (`expected` ≥ 0.6: not a spin, a strobe edit or a whip pan), the frame before them was calm (`lead` ≤ 0.3: not the smeared middle of a shake transition) and the stray picture is unlike its neighbours (`likeness` ≤ 0.5 and 0.25 below the shot's own: not a camera flash on the same scene). Measured: an offline card in a slow shot 1.00 / 1.00 / 0.39, lead 0.01; a light-leak transition into a similar shot (CK O&O 00:14) continuity 0.57; a spinning shot (PEARL SOCIAL_1) expected −0.28; a shake transition's smear (Kiko 16:9 22:02) lead 0.65. A 1-frame shot between two different shots is not flagged (the picture doesn't come back). Segments overlap by 6 frames so a stray frame at the split has its shot before it.
- **Media Offline** (candidates, then a text read). *Candidates*: (1) red runs, per frame at 192 px (`FrameLook.isOffline`): ≥ 60% of the frame in saturated red (Cr ≥ 155, 70 ≤ Cb ≤ 140, Y ≤ 140: excludes orange and magenta; Premiere's card is a vertical gradient, Cr ~200 at the top to ~160 at the bottom, so not "flat") with **something bright on it** (≥ 0.2% of the frame ≥ 40 luma above the red: text or an icon); (2) stray frames; (3) the four longest held pictures (≥ ⅕ s unchanged, `heldRuns`). 2 and 3 because a card with effects or a grade (Lumetri) isn't red. *Confirmation* per candidate run (`OfflineCardReader`, ≤ 10 reads per file, red first; clips without a candidate pay nothing): one frame from the middle of the run at ≤ 1280 px is read with Vision. Offline words (`offlineWords`: Premiere's card in its languages, Resolve) = Media Offline, "card text read". A red run with other words = a red title or end card, dropped; a red run with nothing read (FCP's icon card) is kept only if it stands still (median motion ≤ 1) and its red is flat (`redFlatShare` ≥ 0.75: cards 0.89–0.99, shaded red footage 0.37–0.39), "red card, no text read"; past the read cap red runs count only if one was already confirmed by its words. Stray and held candidates count only with offline words (a stray frame without them stays a flash frame). Red alone was fooled by red footage and by white titles on red (`_TEST`: the Karl Lagerfeld DUO clips), and missed the real card (CK_HOME26_20sec_3x4 16:13: a 1-frame Premiere card, 50% in the old red range). Results rows for Media Offline and flash frames show the frame on hover (`FramePreviewOnHover`, the graphics markers' thumbnail cache; nothing decoded until it opens).

## 8e4. Scan tab → Crop Match (`CropMatch.swift`, `CropMatchViews.swift`)

- **Job**: masters (e.g. a 30 s 9:16) and their cutdowns (15/10/06 s, GIF, same shape): every cutdown shot that's also in its master must be framed exactly like it. Shots may be trimmed, retimed or missing.
- **Sets** (`CropMatchSets`): a batch holds any number of masters, each with any number of cutdowns, found from the names alone (folders don't matter). A video's set name is its file name without its length (`30s`, `06sec`, `:30`, `GIF`), version (`E2.0`, `v3`, `1.1`) and shape (`9x16`) tokens, compared ignoring case, spaces, underscores and dashes; numbers like `01` stay (EDIT_01 ≠ EDIT_02). A set = same set name + same shape read from the file (9:16 and 1:1 versions of an edit are two sets, each with its own master); its longest video is the master, to a tenth of a second (a tolerance between lengths made the sort's order depend on the input's); on equal lengths one in a "master" folder or named so, then the newest version, then by path. Token rules are plain character checks (`kind(of:)`), each name's key computed once and grouped through a dictionary. Measured on a real delivery ("5_CAFE CLOSE-UPS", 20 files across Masters / Cutdowns / "No longer needed" folders): 7 sets, each the right master, no strays, though masters and cutdowns differ in version (E3.0 vs E1.0), one master has a stray space ("FTW_ VIDEO"), one GIF lacks its shape token, and one name sits in two folders. Labels inside a set are the length token, plus the version when the set's versions differ ("10s E1.0"), plus the folder when still equal ("15s E2.0 (Cutdowns)"). Videos with no other version are listed, not compared.
- **1. Fingerprints** (`Fingerprints.read`): one hardware-scaled decode per file at ~96 px (luma), each frame box-averaged to a 16 × 16 grid, zero-mean, unit length (blank frames all zeros: they pair with nothing). Comparing two is a correlation, blind to brightness/contrast. Grid measured on natural-spectrum pictures: at 16 the same shot moved 15 % and zoomed 10 % still correlates ≥ 0.84, different shots ≤ 0.46 (24: 0.81 / 0.43).
- **2. Alignment** (`CropMatcher.align`, Viterbi): each cutdown frame → a master frame or "not in the master". Moving on a frame costs 0; hold 0.12, skip one 0.08, skip two 0.2 (retimes); a jump anywhere 0.8 (a cut); a frame not in the master 0.45 (so frames under ~0.55 correlation with everything leave). Correlations per row are one `vDSP_mmul`; back-pointers one byte per cell. Fingerprints are blurred on purpose, so the path is right to within a few frames, not exactly (step 4 finds the frame).
- **3. Shots** (`CropMatcher.shots`): split where the path jumps, leaves or rejoins the master, or the cutdown cuts (neighbouring frames correlating ≤ 0.5; unpaired stretches split there too, so a punch-in after an absent shot is searched alone). Runs under 3 frames are kept only when every frame pairs at ≥ 0.9 (a fast montage's 1–2 frame shots, which are real edits); others (dissolves, flashes) are dropped, as are 1–2 frame shots too plain to measure (a white flash). Mean pairing correlation < 0.6: "Pairing doubtful". After measuring, neighbouring shots that carry on in the master (next master start 1–3 frames after) with the same verdict and framing (scale within 0.3 %, shift within 2 px) are merged into one row (`merged`): the master's own cut inside a reframed clip, a montage.
- **3b. Punch-ins** (`findPunchIns`): a cutdown section not in the master may be a tighter crop than frame-wide fingerprints survive (the samples' lips shot is 202 %). Its middle frame is compared with crops of every second master frame (the ±4 measuring window finds the exact one) at 1.3, 1.6, 2, 2.5 and 3× on a grid of positions (a tenth of the crop apart), each crop fingerprinted from the master's kept 96 px luma (8-bit) through summed-area tables (`PunchInIndex`: built once per run and only when some cutdown has a shot to look for; each crop's cell bounds worked out once, then every frame tried). Accepted only at ≥ 0.9 (thousands of crops: smooth pictures at 3× correlate easily; a synthetic absent shot matched at 0.81 at 3.3×), and only if measuring confirms it: every measured frame fits ≥ 0.9 and their scales agree within 3 %; otherwise it stays "not in the master". Measuring starts from the crop found (`hintScale/X/Y`).
- **4. Framing** (`FramingMeasurer`, `CropAligner`): three frames per shot (30/50/70 %) decoded exactly at 384 px (`FrameReader.grays`: each pick's window of master frames in one `AVAssetReader` pass from the keyframe before it, hardware-scaled to twice the size, luma only, then area-averaged down; a video with a rotation transform falls back to `AVAssetImageGenerator` frame by frame). A seek per frame decoded from the keyframe again each time and was most of a run's time; going straight to 384 px through the hardware scaler aliased (a 202 % punch-in read 203.0 %, 202.4 % from twice the size). Each image's pyramid is built once (`CropAligner.levels`: the cutdown pick once, each master frame once per shot) and paired (`pyramid(cut:master:)`); resizing uses index maps worked out once, scoring the column sample positions once per call, and a climb never re-scores a position. For each, the master frames ±4 around the pairing are tried and the best fit kept: a pan over a flat scene can make a few frames of timing look like a horizontal reframe; the exact frame matches almost perfectly, its neighbours don't (moving subjects, parallax, blur). Model: master sampled at `centre + (p − centre) / scale + shift`; score = correlation of the cutdown's central 60 % (so a frame cut slightly outside the master still scores). Search: exhaustive at ~24 px (scales 0.76–1.52 in 2 % steps, shifts ±25 %) for the paired frame, ±4 px / ±3 steps around it for its neighbours (or around a punch-in's crop); then at each finer level up to 384 px a climb (±1 px and the scale step, repeated while the fit improves, the step halving per level), a last climb at a quarter step, then a parabola per axis for sub-pixel. A single step per level once stopped at 104 % on a 105 % reframe, and a 1.25 coarse limit read a 130.8 % one as 126.7 %. Measured on synthetic shifts and zooms: within 0.15 px and 0.1 %.
- **Well-fitting frames decide**: of a shot's measured frames, those fitting ≥ `reframeFit` decide when there are any (the biggest difference among them is reported); a poorly fitting one (a title animating, a focus pull) only decides when none fit well. It used to take the biggest difference of all, so one noisy frame overruled good ones (the cafe 10 s 100.5 % read as Check; a 5C shot whose one frame was mid focus-pull read as Check, its other frames framed as the master).
- **Reframes must fit** (`reframeFit` 0.97): a reframe is reported only when the measured crop makes the pictures match that well. Confirmed reframes fit 0.981–0.9998 (a burned-in viewfinder overlay that doesn't scale with the picture holds one at 0.983); shots whose moment, focus or graphics differ from the master's measured 0.82–0.95 and are now "Check" ("Pictures don't match closely: compare by eye · about 108.2%, 23 px right"). `CropMatchShot.fit` / `fitAsIs` keep the numbers.
- **Verdicts**: reframed when the shift or the scale's edge movement is ≥ 1.5 source px and the best fit beats "no change" by ≥ 0.002 (measurement noise on a matching frame doesn't count); the worst of the three frames is reported. Uncertain: too plain to measure (window std < 1.5 %), best fit < 0.8 ("Doesn't match the master closely": another take, graphics over it), or two frames fitting equally (within 0.001) with different verdicts ("Camera move: timing and framing can't be told apart").
- **Batch view** (`CropMatchBatchView`): stats across every set (Masters, Cutdowns, Shots Reframed, Not in Master, To Check); with more than one set, a list of sets (Finder-sidebar rows: name, master length, cutdowns, shape, verdict; the picked one on a soft fill with the accent bar), sorted by name, the first set with a problem picked; then the picked set's name, master file and report; videos with no other version at the end. A list, not tabs: six or more sets overflow a tab strip, and the list shows every set's verdict at once. Within a set, results come back longest first (map rows and cards: master, then e.g. 10 s, 06 s); versions not compared last.
- **Report** (`CropMatchReport.swift`, its own `Equatable` view keyed by `CropMatchRun.id`: expanding a row or hovering the map redraws only the report, never the window; the map's hover state lives in the map). **Version map** (`CropVersionMap`): every version on one time scale in one `Canvas`, under a seconds ruler: the master's bar with the stretches the cutdowns use (one fill per verdict, so stretches several cutdowns use don't stack their translucency), a bar per cutdown with its shots, a hairline apart. Only problems carry colour (red reframed, amber check); framed as the master is a quiet grey, not in the master a hatched outline; a key sits beside the caption. Opened shots carry the accent outline (selection); clicking a coloured shot opens its row (shots framed as the master have none; hover names them); hovering a shot puts it in focus: a veil dims every other bar (lowering opacity instead let overlapping master stretches blend, red over amber reading orange), two dotted lines link the shot's edges to its master stretch's, drawn behind the timelines (the veil covers the bars only, so the lines show clearly between them; curved and filled ribbons were tried and read as heavier), the pair is redrawn on top at full colour with a thin outline, and the caption names it. Bars sit 4 pt in from each side so an outline round the first or last shot isn't cut off (beside the key when both fit, else above it). Labels drop what all file names share (`shortLabels`: "Spot_16x9_10sec" → "10sec"). **Cards**: one per cutdown, a row per shot that isn't framed as the master (timecode, master timecode, "105.0%, 19 px up", length). Clicking a row expands **the master frame with every version's crop drawn on it** (`CropBoxPreview`: every compared shot using any of those master frames, so two cutdowns disagreeing show too; boxes framed as the master sit just inside the edge) and each version's **editor values** (`CropMatchShot.editValues`: the master footage's Scale % and Position on a master-size sequence that give that crop: Scale = scale × 100, Position = centre − shift × scale; the samples' 106.5 % / 1021 shot reads 106.7 % / 1020.7). Side by side when the values fit beside the picture, else below it (`ViewThatFits`; the values never wrap). The frame is decoded only when expanded, through `GlitchThumbnailProvider`'s cache. **Inspect** opens the cutdown in slot A at the measured frame and the master in slot B, linked with the slip that lines up the pair (`slipOffsetFrames = m − c · fpsB / fpsA`), in Difference mode: framed alike, the picture reads black. No Player code changed. The crop picture's long side is 360 pt whatever the shape (a 9:16 master at 360 wide stood 640 tall), decoded at 720 px on its long side. The map's time scale is worked out once per map (every coordinate uses it). Debug screenshots of the report (`QCPIE_FOCUS_ROW=n` puts cutdown n's first flagged shot in focus; `QCPIE_SHOTS_HEIGHT` makes the window taller): `QCPIE_BENCH_CROP=1` with `QCPIE_UI_SHOTS` runs Crop Match on the bench folder first and opens the first flagged row (build with `-Xswiftc -O`: unoptimised, the run outlasts the capture).
- **Validated** on a real master (15 s, 1920 × 1080 H.264) and two cutdowns (10 s, 06 s) with known settings: all six reframes found at their exact timecodes and nothing else flagged; scales 202.5 / 106.7 / 130.7 / 105.0 / 105.4 / 104.6 % against the set 202 / 106.5 / 130.8 / 105 / 105.4 / 104.6 %, and the 106.5 % shot's position (+61 px) as 60.7 px at output scale. Re-cropping each master frame by the measured values and comparing with the cutdown frame (ffmpeg PSNR): 42–48 dB, against 14–26 dB untouched (an exact crop of compressed footage reads ~40–50). It also found a 19 px vertical shift on the 105 % shot that the list didn't mention: 105 % alone compares at 23 dB, with the shift 39–44 dB. Run time in a release build: 2.6 s for the three files (31 s of footage); the cafe delivery (20 files, 7 sets) 6.7 s.
- **Opt-in sample run**: `CROP_SAMPLES=<folder> swift test -c release -Xswiftc -enable-testing --filter CropMatchSamples` prints every shot found (`Tests/CropMatchSamplesTests.swift`; does nothing without the variable).
- **One check at a time**: Line Check, Frame Check and Full Check don't start while Crop Match runs (guards and buttons), as they don't run alongside each other. Inspect on a shot with no master frame clears slot B only if it holds this run's master (left by an earlier Inspect, it showed a meaningless difference); anything else the user put in slot B stays.
- **Sets side by side**: two sets run at a time (a small set, a master and a GIF, leaves the decoder and the cores idle alone); progress is combined across them (`ProgressTally`). Measured on the cafe delivery: 17.0 s → 9.9 s, results identical.
- **Measuring in parallel**: a cutdown's shots are measured in up to 4 lanes (`measure`), each with its own pair of frame readers opened once (an image generator isn't shared between tasks); order kept. A run stopped while a cutdown is being measured leaves that cutdown out (its unmeasured shots would read as framed like the master). Measured on the samples: 13.3 s → 5.2 s, results identical.
- **Cost**: one low-resolution decode per file (like Frame Check, two files at a time) plus ~27 exact-frame decodes and searches per shot. Runs only when asked, never during playback. Tests: `Tests/CropMatchTests.swift` (alignment across cuts, trims, a retime and a missing shot; framing accuracy on known shifts/zooms; end to end on generated H.264 clips with a planted 8 px / 2 % reframe, a 2× punch-in and an absent shot that must not be taken for one).

## 8e2. Inspect → Check Loudness (`Loudness.swift`)

- One decode of the first audio track (`DeliverablesInspector.extractAudioLevels`, Float32 via AVAssetReader) feeds `LoudnessMeter`: K-weighting (vDSP biquads, coefficients for any sample rate), 100 ms sub-blocks → 400 ms momentary / 3 s short-term, gated integrated loudness (−70 abs, −10 rel), LRA (EBU 3342: −20 rel, p10–p95), true peak with the BS.1770-4 Annex 2 48-tap 4× interpolator (vDSP_conv), plus channel notes (silent channel, out of phase, dual mono). Channel weights come from the track's channel layout labels (LFE excluded, surrounds 1.41; AAC 5.1 decodes C L R Ls Rs LFE, so never assume an order when labels exist); unlabelled 6-channel audio is taken as SMPTE order. Clips shorter than one 400 ms block are measured as a single block. Late results of a cancelled run are dropped (`audioAnalysisRun`).
- `peakDB` = true peak; mute = nothing above the gate or true peak < −60 dBTP. Pass/warn/fail is evaluated at display/export time against `LoudnessTarget` (`prefLoudnessTarget`, Settings → Loudness), so changing the target recolours without re-measuring.
- **Benchmark**: `scripts/LoudnessBench/run.sh` compares against ffmpeg `ebur128=peak=true` (integrated ±0.1 LU, true peak ±0.5 dB, LRA ±0.5 LU) and an exact inter-sample-peak case (ffmpeg over-reads it). Must print ALL PASSED.

## 8e3. Legal Range (`LegalRange.swift`: Frame Check + Player zebra)

- Presets (`LegalRangeSpec`): **EBU R103 (UK)** is the default (luma −1…103 %, R′G′B′ −5…105 %, frames flagged when > 1 % of the picture is out), Strict 0…100 %. The choice lives on `PlayerEngine.legalRangePreset` (mirrored to UserDefaults `prefLegalRangePreset`), shared by the Scan tab menu and the zebra's context menu; Frame Check reads it at scan start.
- **Frame Check decodes narrow range (`420v`)**: a full-range output clips super-whites/blacks before they can be measured (verified: Y 250 decodes as 255). The legal measure runs on the raw codes; the other Frame Check measures get a LUT expansion to full range, so their thresholds are unchanged.
- Measured per 2×2 block (`LegalRangeBlocks`): luma per pixel, gamut with the block's mean luma, then 4-neighbour erosion. Without these, 4:2:0 chroma smear at hard edges (white text on red reads 130 %) and scaler/codec ringing flag clean graphics and colour bars; at the 192 px analysis size an un-eroded check flagged a `_TEST` clip that a full-resolution check (0.25 % of pixels) shows legal. Flagged frames ≤ ½ s apart form one run.
- **Zebra** (`showLegalZebra`): sublayers of `stillFrameLayerA/B` (they inherit split masks, frames and visibility), **paused only**, hidden while playing/scrubbing and in difference/overlay modes. Each mask is one frame decoded with `AVAssetReader` off the main thread (≤ 1920 px, ~30 ms at 1080p long-GOP) 80 ms after stepping settles, keyed by file/frame/preset; nothing runs on the playback or scrub path. It shows source levels (no EV), same blocks as the scan. Image sequences, stills and audio have no zebra.
- Benchmark: `scripts/FrameCheckBench/run.sh` includes super-white, super-black, illegal-colour, sub-1 % speck and full-swing bars cases plus zebra frame accuracy (H.264 long GOP, ProRes). Must print ALL PASSED.

## 8e4. Pro Video Formats (`ProVideoFormats.swift`)

- `App.init` registers Apple's Pro Video Formats decoders and format readers (`VTRegisterProfessionalVideoWorkflowVideoDecoders`, `MTRegisterProfessionalVideoWorkflowFormatReaders`) before any media is opened, only when the plug-ins folder is non-empty (registration costs ~17 ms at launch even with nothing installed; the folder check is microseconds), so MXF, AVC-Intra, XAVC and DNxHD/HR go through the normal AVFoundation pipeline. Existing formats are unaffected.
- The package can't be bundled or installed silently (admin install, Apple distributes it via Software Update to Macs with Final Cut Pro/Motion/Compressor). Opening an MXF without it (`/Library/Video/Professional Video Workflow Plug-Ins` empty) shows `ProVideoFormatsPrompt` once per session; scans report "Needs Apple Pro Video Formats".
- AVC-Intra/XAVC 10-bit 4:2:2 most likely decode in software: expect slower 4K playback and scans than hardware H.264/HEVC.


## 8e4b. Files macOS can't open: specs from the bundled ffprobe (`FFprobe.swift`, `DeliverablesInspector+FFprobe.swift`)

- Inspect only, and never for viewing: no proxies, nothing decoded. When AVFoundation can't open a file (WebM, MKV, AVI, WMV, VP9, AV1 before M3, MXF without Pro Video Formats), `inspectFile` runs the bundled ffprobe (`-show_format -show_streams` plus the first 5 s of packet times) and maps it onto the same `DeliverableAsset` fields, so Name Mismatch, column targets and the Delivery Plan compare it like any file. `specsOnlyReason` ("macOS can't play VP9 in WEBM", or "Install Apple Pro Video Formats to play it") marks it: an eye-slash in the Video cell, the reason in the check cells, the preview and the Player's toast; Inspect's checks (loudness, end frames, subs & graphics) skip it (`checkTargets`). If ffprobe can't read it either, it's Unreadable as before (damaged, empty, still being written).
- Frame rate: from the packet times when the header disagrees by more than 3% (WebM written at a variable rate says 60, DV 60000; MKV rounds times to the millisecond, AVI repeats some), except field-coded interlaced video, whose packets are fields; snapped to the standard rates. Spread packet intervals add "variable frame rate" to the reason. Size: pixels as stored, turned for a quarter-turn display matrix (as AVFoundation does; pixel aspect isn't applied, as for files macOS reads). Duration: the container's, else the longest stream's. Frames: duration × rate, as for AVFoundation files. Cover art in audio files (attached pictures) isn't video.
- Not for MOV / MP4 / WAV and the other containers macOS opens whatever the codec (`nativeContainers`): failing to open one means it's damaged, so it stays Unreadable (unless it needs Pro Video Formats). Cut off after the header (a copy still running): a second run reads the packets from 2 s before the end (`lastPacketTime`, absolute times: TS starts at 1.4 s) and flags "CUT OFF" when they stop early, as `presentFraction` does for files macOS reads; skipped when the first run already read a short clip to its end, and no answer flags nothing. Upload's pre-flight accepts files ffprobe reads (it called every MKV "damaged") unless they're cut off. Inspect's preview turns a late AVPlayer failure into the same "Can't preview" card; Media Info (⌘I) shows the specs read, not AVFoundation defaults. Damaged headers' huge numbers are clamped, packets without a time skipped. Thumbnails that fail aren't retried for a minute (`GlitchThumbnailProvider.failed`).
- Running: off the main thread, at most 4 at once (`Gate`); a run still waiting for its turn when Inspect moves on (cancelled task) doesn't start. Input goes through the `file:` protocol (names with `:`, `%`, `?` aren't read as protocols or patterns). The timeout timer is cancelled as soon as a run finishes: left sleeping, it kept each run's process and pipe for 20 s, and a few hundred files ran an app opened from the Finder (256 descriptors) out of them. A run killed by a signal it didn't get from QCpie is logged (e.g. macOS refusing the helper). `BuildApp.sh` signs the helper on its own (`--deep` skips Resources). At 20 s ffprobe is terminated (killed 2 s later) and the caller gets nil at once: a read stuck on a dead network drive can outlive a kill. Waits through the termination handler (`waitUntilExit()` in async code hung after ffprobe had exited). ~10 ms a run (112 MB 1080p MKV, 9-stream TS), one or two runs a file; only for files AVFoundation failed on, so nothing changes for anything macOS reads, and nothing runs at launch or near playback.
- Binary: `scripts/build_ffprobe.sh` builds ffprobe 9.0.2 from FFmpeg's release tarball (SHA-256 pinned, cross-checked with Homebrew's formula), LGPL only (no `--enable-gpl`, no external libraries), demuxers/parsers/decoders but no encoders, muxers, filters, devices or network; arm64, macOS 14+, ~8.6 MB, linked to system frameworks only. Output `Resources/Helpers/` (gitignored); `BuildApp.sh` copies it with `FFMPEG_LICENSE.txt` into `Contents/Resources/Helpers`, `Release.sh build` builds it if missing and stops if the app lacks it. Lookup: `QCPIE_FFPROBE`, the app bundle, then the repository (debug runs, `swift test`). Without it, files read as before.
- Tests: `FFprobeTests` (saved ffprobe output for rates, rotation, cover art, PCM, subtitles, reasons; timeout; a real WebM where FFmpeg and the bundled ffprobe exist).

## 8f2. Check Subs & Graphics (Inspect)

- **What:** Inspect's left panel → Check Subs & Graphics (`SpecsState.checkPictureText`, two files at a time, each on a dispatch thread at `.utility`; progress is the per-file count like Check End Frames). `PictureTextScanner` (VideoQCLib) decodes at ≤ 1920 px (`BurnedSubtitleReader.decodeSize`, rotation applied), samples 2 frames/s plus the last frame (an end logo can sit in the final half second), and reads each whole frame with Vision (accurate, no language correction, language detected). Text needs confidence ≥ 0.4 and two letters or digits.
- **Classify** (`classify`, pure, `Tests/PictureTextTests.swift`): a line wider than tall in pixels (≥ 1.5×: text printed on a product or a rotated logo isn't), centred (|midX − 0.5| < 0.2), in the lower 35% (45% for portrait pictures: social captions sit higher), in 3+ samples with 2+ different lines, or one sentence-like line (4+ words) that comes, goes and comes back (a repeated subtitle, as in CK_HOME26_30sec_16x9_E3.0) = **subtitles likely**. Not subtitles: a constant tagline, off-centre lower thirds, more than three lines at once (credits, text cards). Every other text at least 2% of the frame tall = **graphics**, as appearances (`appearance`): consecutive samples are one appearance while more than half of the previous sample's text is still there (text building up on a card) or more than half of the new sample's text was already there (text going away); readings match when close or one is inside the other (`related`: a title typing itself out). So all the words of a title card are one appearance (up to six readings), a new card sharing one word (a brand name) is another, and a logo at the start and again at the end is two; each gets a Player marker. In clips of 20 s or more, text in 60% of the samples with no break over 2 s (a corner logo, a channel bug) is its own appearance and is taken out first, so it doesn't glue every title together. Text that changed every sample (typed or animated) keeps its fullest reading. A lone sample next to an appearance (a card wiping into the next, animated text) joins it; a lone sample on its own counts only when big (≥ 5%: a short end logo) and not running sideways. Within an appearance, readings seen once are dropped (unless big), a reading inside a fuller one is a fragment ("VIBES" of "ADIDAS VIBES"), and misread copies keep the longer reading. Stray marks at a line's edges (/ | - ·) are trimmed. Up to 30 appearances per file; the column lists each text once (`graphicTexts`). Neither = **CLEAN**. Text only: logos without letters aren't seen; text in the footage (signs, labels) counts, so the tooltip lists what was read and when.
- **Name check** (`PictureTextCheck.nameMismatches`): CLEAN / TEXTLESS / NOTEXT / NO TEXT with any text, TITLED / TITLES / LOGO / SUPERS / TXT without graphics, SUB / SUBS / SUBBED / SUBTITLED / SUBTITLES / OCAP(S) without subtitles → red cell with ⚠. Whole tokens (CLEANING, SUBWAY don't count); a word after NO / WITHOUT / WO is a negation (NO_LOGO promises nothing); a name promising both clean and text promises nothing. It counts as the row's mismatch everywhere (row tint, mismatch count and filter, right-click Dismiss / Restore, exports' status and notes).
- **Nothing to check / can't read:** audio, stills and image-sequence folders show — (`isUnavailable`). A video that fails to decode, or whose readable part ends before its duration (cut short, drive gone), is CAN'T READ: a partial read is never reported as clean.
- **Re-reading:** when Inspect reads files again (Refresh, the list replaced), their markers are cleared with their old results (`PictureTextMarks.clear`).
- **Performance:** the scan decodes in the decoder's own 4:2:0 format, which Vision reads directly (converting every frame to BGRA, most never read, was more than half the decode: 0.93 s → 0.39 s per 30 s of 1080p H.264). Reading text costs ~35–45 ms a frame whatever the settings (frame size, languages, revision, minimum text height, compute device) and Vision runs one read at a time per process (2, 4 or 8 threads: same 185 s on the v3 mock; separate processes do scale, 4 ≈ 3×, hence the helpers below), and otherwise the saving is reading fewer frames: a sample whose 48×27 luma grid matches the last frame read (no cell moved > 2 levels, `sameFrame`) reuses its text, and a half-second sample waits for the next whole second and is read only when either neighbour has text or a quick `VNDetectTextRectanglesRequest` (~1 ms) finds some. Neither the detector nor the fast reader can gate every frame: both miss the JIMMY CHOO wordmark (PEARL 26_SOCIAL_2). Measured: v3 mock 215 → 92 s, real spots (PictureTextBench) 18.3 → 16.9 s (footage keeps moving), same result for every file. `PictureTextCheck.graphics` / `graphicTexts` are stored, recomputed only when the readings or dismissals change, and the Subs / Text on Screen sort ranks each file once: sorting 1,000 checked files took 13 s (every comparison re-parsed names and re-ran the fuzzy dismissal match), now ~20 ms; chip counts 563 → 8 ms, CSV 1.5 s → 25 ms (debug build; guarded by `largeList` in `PictureTextTests`).
- **Helper processes** (`PictureTextWorkers`): on Macs with the memory, a check also starts copies of QCpie in worker mode (`main.swift` checks `--picture-text-worker` before any UI; the worker registers Pro Video Formats, never writes QCpie.log). Count by RAM (`recommendedCount`, ~200 MB each): none under 12 GB (8 GB Airs), 2 under 24 GB, else 4 (8 add little), never more than the files beyond the app's own two lanes. Each reads one file at a time and sends its `PictureTextScanner.Reading` back as JSON lines on stdout; the app classifies, so results are identical (`helperProcesses` test). Workers pause mid-file while the Player plays or scrubs (`PlaybackActivity`, set from `PlayerEngine.isPlaying` / `isScrubbing`), in Low Power Mode or when the Mac runs hot (thermal state serious); the app's own two lanes carry on as before. Pausing is a message, not SIGSTOP: a worker quits whenever its stdin closes (scan done or cancelled, QCpie quit or killed), paused or not, so none is left behind. A worker that dies mid-file has that file read in the app; one that can't start leaves the app's lanes. Measured (M4 Max, release): v3 mock 151 files 58.8 → 31.3 s (2 helpers) → 27.0 s (4); 7 real CK spots 8.0 → 4.9 s.
- **Timeline markers:** each result also goes to `PictureTextMarks.shared` (by standardized URL, published only when a result lands). `PictureTextTimelineMarks` on the Player ruler draws a pink diamond (`StudioTheme.graphicsMarker`) at the start of each appearance of text graphics in the clip on screen with its text in the tooltip; clicking one pauses and seeks to that frame. No decoding, nothing per frame.
- **Progress:** files done plus the share read of files in progress (`PictureTextProgress`, its own object read through `ObservingView`, ≤ 2 updates a second per file), so a long film doesn't sit at 0/1.
- **Columns:** Subs (LIKELY (N lines) / NONE; click opens the Player at the first example) and Text on Screen (the texts once each, or CLEAN / NONE), sortable (name mismatches first). Clicking Text on Screen opens `PictureTextListPopover`: each appearance with a frame thumbnail (`PictureTextThumb`, through `GlitchThumbnailProvider`, decoded only when shown), its text and times; a row opens the Player there.
- **Not a Graphic** (the eye-slash on a row of that popover): the appearance's texts go into `PictureTextCheck.dismissed` (normalised), so `graphics` leaves them out everywhere: column, markers, chips, name check, exports. Saved per file in UserDefaults `dismissedGraphics` (standardized path → texts) and applied to later checks; Restore in the popover or the row's right-click menu brings them back. `allGraphics` keeps what was read.
- **Chips** (`PictureTextFilter`, `SpecsState.pictureTextFilter`, part of `displayedAssets`' key): All Checked · Subs · Text on Screen · Clean · Name Mismatch, with counts over the checked files (cached per `assetsVersion`); shown once any file has been checked. In memory like End Frame (not saved), kept through Check Loudness, cleared when the list is replaced. CSV / Sheets exports add "Burned-in Subs" and "Graphics (Text)".
- **Measured** (`scripts/PictureTextBench`, M4 Max, 14 real `_TEST` deliverables with known answers): all right (3 CLEAN, 11 with titles or text logos, including white text over a busy gold heel and a white logo on light grey; an MP3 and a JPG as nothing to check), 13× real time. Real burned-in subtitles were only checked on generated clips so far (the LNEH clip is on RIC_2TB, listed in `expected.txt`).
